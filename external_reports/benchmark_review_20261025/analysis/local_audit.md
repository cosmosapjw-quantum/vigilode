# 로컬 벤치마크 자료의 독립 점검

2026-10-25 기준 코드 `2a4bf90d1445b67542bdac5030b4c5d10da20445`를 읽고 게시 자료를 재분석하였다. 솔버를 새로 실행하지 않았다.

## 자료와 비교 범위

최신 압축 자료에는 1,539개 실행의 최종 상태가 있다. 전체 시간·오차·작업량은 원래 로컬 실행 폴더에 남아 있으며, 저장소에는 여섯 대표 실패 실행의 원자료가 포함되어 있다. 따라서 압축 자료로 정확도별 완료율과 실패 분포를 그릴 수 있고, 속도 그래프에는 실제 시간 자료를 별도로 연결해야 한다. 사례 2·3·5의 참조 후보가 추가되었지만 기존 805개의 참조 미확정 실행을 자동 재분류하지 않는다.

Native DVODE와 diffsol 비교는 컴파일된 callback을 사용한다. `compare.py`가 저장하는 `eligible_speed_ratios_vs_dopri5`의 정의는 T_method/T_DOPRI5이므로 1보다 크면 시간이 더 오래 걸린다. 보고서에서는 정규화 시간으로 표시한다. 구성·분해·워크스페이스 생성의 타이머 포함 범위도 서로 구분한다.

## 실패 자료가 보여주는 병목

경계층 사례 5의 DOPRI5 실행은 독립 궤적 256개를 2개 스레드에서 계산했다. 첫 궤적은 200,000회 시도 중 195,112회를 수락하고 t=0.645495998875149에서 정지하였다. 전체 RHS callback은 307,200,256회였고 내부 측정시간은 15.470179546초였다. 사용자 CPU 시간은 30.83초, 커널 CPU 시간은 0초로 기록되었다. 목표 시각을 끝내지 못한 원인은 시도 횟수 한도다.

Kuramoto–Sivashinsky 사례 12의 8개 스레드 데이터 병렬 실행도 시도 횟수 한도에 도달했다. 내부 시간 32.739113137초 동안 RHS를 1,200,001회 호출하고 t=3.757461472896645에 도달했다. GNU time에는 사용자 CPU 135.76초, 커널 CPU 84.51초, 비자발적 문맥 전환 15,412,957회가 기록되어 있다. 커널 CPU 시간의 비율은 38.37%다. 이 자료는 스레드 동기화·스케줄링 비용을 조사할 우선순위를 제시한다. 동일 조건의 직렬 실행과 비교하면 그 기여를 더 좁힐 수 있다. CPU 시간은 여러 스레드의 합이므로 벽시계 시간과 같은 축에서 쌓지 않는다.

네 timeout의 `resource.txt`는 비어 있다. 해당 실행의 CPU/RSS나 최종 오차를 복원하지 않는다. 보존된 60초 전후의 프로세스 시간은 완료 시간의 우측 절단값으로 취급한다.

## 진행 중인 실행에 대한 조치

기존 솔버와 실행기를 수정하거나 현재 프로세스를 재시작할 필요는 없다. 저장소의 압축 실행기 사본은 보관용이고 실제 작업은 고정된 로컬 실행 폴더에서 진행 중이다. 추가 작업은 종료 영수증의 읽기 전용 내보내기로 한정한다.

새 `tools/export_local_measurements.py`는 종료 영수증, stdout/stderr/resource 해시, 저장 결과와 raw 결과의 동일성, case/method/layer/thread 계약을 확인한다. 시간·오차·작업량·참조 및 타이밍 범위·소스 식별자를 내보내고 큰 상태 벡터는 원래 폴더에 남긴다. START만 있는 실행은 진행 중/중단 미확정으로 표시하며 건드리지 않는다. wrapper와 원래 영수증은 같은 `raw_evidence_key`를 갖는다.

합성 경계 검사에서 과거 native 비교기의 `assess` 함수는 NaN 종료 시각을 수락하였다. 실제 측정 중 그러한 행이 발생했다는 근거는 없다. 새 내보내기는 비유한 JSON 및 비유한 종료 시각을 거부하여 후처리 입력을 강화한다.

15개 fixture 검사가 통과했다. 게시된 여섯 실패 실행 모두 raw 해시와 결과 동일성을 확인했으며, 1,539개 목록의 해당 영수증 해시와 일치하였다. 여섯 실행은 원래 실패 상태를 유지한다. 검사 영수증과 내보내기는 `EXPORTER_VALIDATION.json`, `exported_failure_measurements_v2/`에 있다.
