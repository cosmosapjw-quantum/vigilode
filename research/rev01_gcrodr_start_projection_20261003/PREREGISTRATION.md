# Preregistration: GCRO-DR with the first Arnoldi vector orthogonalized against the recycle images (review DAG node REV-01)

## Question

INT-01 (L-0052) left two recycled-GCRO-DR failures. Critical review C3 locates a structural cause in the code:

- After the recycle projection, the solver recomputes the true (preconditioned) residual `r` and builds `v_1 = r /
  ||r||` without projecting `r` against `C` again.
- The small least-squares problem `min ||[C V]^T r - G y||` equals the true residual minimization only if `[C V]` is
  orthonormal and `r` lies in its span.
- A defect in `M^-1 A U = C` leaves a component of `r` along `C`, and the projection removed almost all of `r`, so
  that component is O(1) relative to what remains (`max |C^T V| = 0.64` in the first cycle of both failures).

The proposed fix is to build `v_1` from `r - C C^T r`, while keeping `r` itself in the right-hand side `[C V]^T r`.
Then `r = C (C^T r) + beta v_1` lies in the span of an orthonormal `[C V]`, and the small problem is exact for the
current relation. Does this remove the recycle-induced failures, alone or with INT-01's reuse check, on the L-0046
sets and on a fresh set that can fail?

## Changes (opt-in; defaults unchanged)

`rodas5p-krylov`:

- `GcrodrSolveOptions { policy: GcrodrReusePolicy, orthogonalize_start: bool }` and
  `solve_gcrodr_with_options(op, pc, rhs, x0, config, state, residual_scale, workspace, options, trace, counters)`.
  `solve_gcrodr_with_policy` becomes this with `orthogonalize_start = false`.
- With `orthogonalize_start` and recycle rank `k > 0`, the cycle's first basis vector is `w = r - sum_j c_j (c_j^T
  r)`, applied twice (classical Gram-Schmidt with one reorthogonalization), and `v_1 = w / ||w||`. Its dot products
  and updates are charged to the counters. The right-hand side of the small problem stays `[C V]^T r`. Nothing else
  changes.

## Controls

The same sequences and GCRO-DR settings as L-0052, one carried state per control: B cold GCRO-DR, C recycled, E
recycled with the 1e-8 reuse check, **F recycled with `orthogonalize_start`**, and **EF** with both. A (cold GMRES) is
the reference for false convergence.

## Systems

1. **L-0046/L-0052 sets**, regenerated by the same code: the trajectory set (320 solves) and the one-step set (16).
2. **Fresh Brusselator set** (not used before): Brusselator 1-D with 80 cells (n = 160). The trajectory set is the
   first 40 attempts of the GMRES U-form run on `[0, 10]` (rtol 1e-11, budget 200). The one-step set is h = 1e-4 and
   1e-2 (rtol 1e-12, budget 4000). Only control C has been run on it, to check that the set can fail (P1 of the
   critical review). That run gave 30 failures in the 320 trajectory solves and 6 in the 16 one-step solves (generating run: 92 attempts, success). No other control was run before this commit.
3. **INT-01's fresh convection-diffusion-reaction family** (288 solves; no control failed on it in L-0052), as a
   no-harm check.

## Gate

**PASS** if all hold:

1. **Defaults unchanged.** `solve_gcrodr_with_options` with `orthogonalize_start = false` is bitwise
   `solve_gcrodr_with_policy` (solution, report, counters, state, trace) on the contract systems. The INT-01 and
   R-NEXT-03 contract tests pass.
2. **Failures removed.** Control F has no failure on sets 1 and 2 where cold GCRO-DR (B) succeeds.
3. **No false convergence and full accounting.** These are the same rules as L-0052 item 4, for every GCRO-DR
   control and every set. Each completed cycle of F and EF may also charge `2k` dot products and `2k` vector updates
   for the start projection; those count no operator products.
4. **No harm on set 3.** F fails on no more set-3 solves than C.

Otherwise **FAIL**. Reported, not gated (P1): failures and products per control and set, F and EF against B and C,
and `max |C^T V|` per cycle.

## Stop condition

Any false convergence, or an uncharged product, stops the option.
