# 자동 선택 진입부의 가용성 계약과 RHS 전용 경로

## 문제와 수정

자동 선택은 명시적 방법으로 출발하고 관찰된 계산량에 따라 허가된 암시적 방법을 비교한다. 그러나 기존 `AutomaticOde`는 미분 사용이 허용되면 문제를 곧바로 `ProblemRegime::Stiff`로 간주하여 `GeneralOde::select`에 넘겼다. 따라서 RHS만으로 풀 수 있는 초기값 문제도 제공된 Jacobian/JVP가 없거나, dense 차원 제한을 넘거나, matrix-free 사용이 허가되지 않았다는 이유로 적분 전에 거절되었다. 방법 사용을 허가하는 설정이 오히려 실행 가능한 문제의 범위를 줄이는 셈이었다. 이는 강성 판별 결과가 아니라 진입부의 계약 오류이다.

수정 후에는 전체 요청의 유효성과 선택적 비교 방법의 가용성을 분리한다. 먼저 identity mass, endpoint 관측, 무이벤트 조건을 검사한다. 미분을 허용한 경우에는 잘못된 band 선언, band provider 불일치, autonomous와 시간 미분의 중복 선언을 검사한다. 이어서 암시적 방법의 기능을 조회한다. 다음 여섯 이유는 암시적 비교 방법을 사용할 수 없다는 뜻으로만 해석하고, 실제 적분은 RHS 전용 경로로 진행한다.

| 암시적 비교 방법의 제약 | 실제 동작 |
|---|---|
| `ProvidedOnly`에서 Jacobian/JVP 미제공 | RHS 전용 |
| `ProvidedOnly`에서 nonautonomous 문제의 시간 미분 미제공 | RHS 전용 |
| dense 행렬 차원 제한 초과 | RHS 전용; dense callback 미호출 |
| matrix-free 실행 허가 없음 | RHS 전용; JVP 미호출 |
| JVP 경로의 성분별 절대오차 허용치 미지원 | 원래 성분별 허용치를 유지한 RHS 전용 |
| dense provider와 band 선언 조합의 성분별 절대오차 허용치 미지원 | 원래 성분별 허용치를 유지한 RHS 전용 |

이 여섯 항목은 명시적으로 열거하였다. 새로운 미지원 기능을 포괄적으로 무시하지 않는다. mass, event, dense output 요구는 계속 오류이며 수치 입력 오류도 적분 전에 거절한다. JVP와 band의 양립 불가능한 선언도 유지해서 거절한다. 실제 `Problem`과 `Options`에는 sensitivity 요청 필드가 없으므로 이번 변경에서 sensitivity 지원을 주장하거나 가상의 입력 검사를 추가하지 않았다.

콜백 재실행 허가 역시 실제 비교가 가능한 경우에만 요구한다. RHS 전용으로 제한되면 비교 적분 자체가 실행되지 않는다. 반환값은 기존 완료 또는 실패 메시지를 보존한 뒤 비교 방법의 불가 사유를 덧붙인다. 각 실행 구간의 `decision`에도 같은 사유를 기록하고, 실제 `config.fallback`은 `Forbidden`으로 남긴다. 이 표시는 비강성 판정을 의미하지 않는다. 명시적 적분이 강성 때문에 예산을 소진하면 실패 상태, 마지막 유효 상태, 소비한 시도 수를 그대로 반환한다.

## 정리: 미분 허가와 실행 가능성의 분리

전체 문제 계약과 수치 입력 검사를 통과하는 요청을 \(P\), RHS 전용 적분을 \(E(P)\), 선택적 암시적 방법의 사전 가용성 검사를 \(A(P,\pi)\)라 하자. \(\pi\)는 미분 및 자원 허가이다. \(A\)가 위에 열거된 사유 중 하나로 불가이고 미분 선언에 모순이 없다면, 수정된 자동 선택은 \(E(P)\)를 실행한다. 따라서 이 경우 미분 허가의 추가만으로 RHS 전용 실행이 사전 거절되는 일은 없다.

증명은 실행 분기에서 직접 따른다. 전체 기능 검사는 암시적 방법 조회보다 먼저 수행한다. 열거된 불가 사유를 얻으면 유효 fallback을 `Forbidden`으로 바꾸고, 그 외의 수치 옵션과 초기 조건은 그대로 유지한다. 이 설정은 `SwitchingSolver`의 기존 `persistent_explicit` 분기를 선택한다. 해당 분기는 Jacobian, JVP, 시간 미분 또는 암시적 비교를 호출하지 않고 `Dopri5::solve_observed`를 한 번 실행한다. 재실행 허가 검사는 이 분기에는 적용되지 않는다. 따라서 결과는 해당 관측 시각을 직접 지정한 RHS 전용 실행과 같은 수치 경로를 따른다. 메시지와 선택 기록만 불가 사유를 추가한다. □

이 명제는 명시적 방법의 안정영역을 확대하지 않으며 전체 적분의 성공을 보장하지 않는다. 해결한 것은 선택적 자원 부재를 전체 문제의 불가능성과 혼동하던 오류이다. 따라서 실패한 명시적 결과를 성공으로 바꾸는 분기는 없다.

## 비용과 관측 계약

새로운 사전 검사는 문제 구조와 설정만 조회하며 사용자 콜백을 호출하지 않는다. 벡터나 행렬 크기에 비례하는 수치 연산도 추가하지 않는다. 사전 확인의 비용은 차원에 대해 상수이다. fallback 사유 문자열을 결과에 기록하는 비용은 적분 종료 시 한 번 발생한다.

최신 native 코드에는 이미 하나의 `Dopri5::solve_observed`가 기본 여덟 구간의 관측 시각을 모두 처리하는 RHS 전용 경로가 있었다. FSAL 값과 작업공간을 보존하므로 이번 변경이 이를 처음 도입했다고 서술해서는 안 된다. 이번 수정은 기존 경로를 선택적 암시적 방법의 부재에도 사용할 수 있게 확장한다.

관측점은 API 결과의 일부이다. 이를 두 끝점으로 줄여 빠르게 만드는 방안은 채택하지 않았다. dense interpolation으로 관측값을 만드는 방안 역시 현재의 각 시각에 정확히 착지하는 수치 경로와 다르므로 별도의 출력 정확도 검증 없이 대체하지 않았다. 기본 경로는 초기 시각과 여덟 관측점을 그대로 반환한다. 이번 진입부 수정에서 경과시간 단축률을 주장하지 않는다. 직접 RHS 전용 실행과의 시도 수, RHS 호출 수, 관측 상태 일치는 회귀검증 대상으로 삼았다.

## 분기 탐색과 선택

| 후보 | 결론 | 근거와 다음 행동 |
|---|---|---|
| 전체 요청과 선택적 비교 방법의 가용성 분리 | 구현 | 기존 사용 허가를 지키면서 유효한 RHS 실행을 복구한다. |
| 가용한 방법에 대해서만 재실행 허가 요구 | 구현 | 실제 재실행이 없는 경우 허가 의무를 부과할 이유가 없다. |
| 기존 persistent RHS 관측 경로 재사용 | 유지 | 새로운 수치 방법이나 중복 작업공간이 필요 없다. |
| 여덟 관측점을 숨기고 끝점만 반환 | 제외 | 공개 결과의 의미를 바꾼다. |
| 보간으로 관측 착지 비용 제거 | 후속 실험 | 출력 정확도와 비용의 비교가 먼저 필요하다. 현재 경로의 무조건 대체는 하지 않는다. |
| 모든 암시적 거절을 RHS 실행으로 대체 | 제외 | 잘못된 기능 요청이나 향후 제약을 숨길 수 있다. 알려진 선택적 제약만 허용한다. |
| 기본 자동 선택을 비강성 인증으로 해석 | 제외 | 제공자 부재나 허가 제한은 물리적 강성에 관한 증거가 아니다. |

## 회귀검증과 다음 개발 단계

`automatic_availability_contracts.rs`에는 두 자동 선택 진입점에서의 미제공 provider 처리, 시간 미분 부재, 성분별 허용치 보존, 기존 RHS 경로와 정확히 같은 출력·작업량, 전체 기능 요청의 사전 거절, 잘못된 수치 입력의 거절, 지원하지 않는 provider 선언, 가용한 후보의 재실행 허가, 잘못된 미분 선언, 예산 소진 후 실패 보존을 포함하였다. 실제 사용자 RHS 호출을 원자 카운터로 세어 내부 통계와 비교하는 검사도 포함한다. 기존 `automatic_adapter_contracts.rs`의 두 자원 제한 검사는 이제 허가되지 않은 콜백을 호출하지 않고 명시적 경로로 진행하는 계약을 검사한다.

이 문서는 구현과 검증 설계를 기록한다. 실제 Cargo 실행 및 결과는 통합 작업의 테스트 영수증에서 확인해야 한다. 작성 시점에 이 담당 작업은 Cargo 실행을 하지 않았다.

다음 단계는 세 가지이다. 첫째, 선택적 선언 검사가 `SwitchingSolver::validate`와 의미상 일치하도록 공통 순수 검사 함수로 추출한다. 이번 변경에서는 다른 파일의 병렬 수정과 충돌하지 않도록 검사 내용을 동일하게 유지했다. 둘째, 반환 결과에 문자열을 분석하지 않아도 되는 구조화된 방법 가용성 기록을 추가한다. 기존 스키마를 변경할 때에는 요청된 허가와 실제 적용된 허가를 모두 보존한다. 셋째, 종료점만 필요한 별도 API와 관측 시각이 필요한 API를 분리하여 출력 계약을 명시한 뒤 비용을 비교한다. 동일한 API에서 결과를 몰래 생략하는 방식은 사용하지 않는다.
