# VigilODE 비강성 적분 확장과 생산 사용 적합성 재감사

작업 식별자: `nonstiff_explicit_20261023`. 기준 코드: `4929c0f86cee03a06ac1ab2713e1b438dd10cfc5`. 검증·성능 측정 소스: `45037fc24e8f8101605f309e1fdb3a9a4e3df56d`. 이번 실행은 로컬 환경만 사용했다.

## 1. 연구 동기와 판단 기준

강성 적분기의 안정성은 모든 문제에서 같은 가치를 갖지 않는다. 비강성 문제에서는 정확도가 요구하는 단계 크기로 명시적 방법을 안정하게 사용할 수 있는 반면, 매 단계 자코비안 구성과 선형계 풀이의 비용은 여전히 발생한다. 기존 공개 `Rodas5p` 경로는 RHS만 제공한 문제에도 유한차분 자코비안 경로를 사용했다. 사용자가 도함수를 제공하지 않았다는 사실은 강성 여부를 판별하는 정보가 아니므로, 기존 경로의 의미를 바꾸지 않고 독립적인 명시적 진입점을 추가했다.

이번에 구현한 것은 Dormand–Prince 5(4), FSAL 재사용, 성분별 허용오차, 명시적 실패 처리, 독립 궤적 병렬화이다. 새로운 계수를 제안하는 연구가 아니라, 검증된 방법을 기존 코드의 관측 시각·오차 제어·오류 계약에 연결하고 그 효과를 측정하는 연구다. 단계 병렬 반복과 안정화 다항식은 별도 수학적 구성으로 분석했다.

범용 생산 사용 적격성과 특정 기능의 사용 가능성은 구분해야 한다. 새 경로의 지원 범위는 **전진·단위 질량·매끄러운 비강성 IVP, 고정된 모델, scalar/vector atol, 종점 관측**이다. 사건 위치 추적, 연속 출력, 비항등 질량 행렬과 자동 강성 전환은 지원하지 않는다. 따라서 이 범위를 만족하고 문제별 정확도 검증을 거친 경우의 명시적 선택은 가능하지만, 모든 문제를 자동 처리하는 범용 production solver로 승격할 근거는 아직 충분하지 않다.

## 2. 소스와 기존 연구의 통합

별도 개발 계열이 통합된 기준 코드와, 최신 별도 응용 연구 `69e83044aacfb9a8fd2c6c3fb1146911beeedd79`를 함께 확인했다. 후자는 축약된 30개 변수의 적분을 복원된 33개 물리 변수 norm으로 제어하는 Python BDF 연구다. 이 변경은 native Rust 적분기의 수정이 아니며, 해당 BDF 제어식의 predictor/endpoint 규약을 DOPRI의 `max(|old|,|new|)` 스케일과 동일하게 취급하지 않았다. 향후 native 축약 클라이언트에서는 상태 lift와 오차 tangent lift를 함께 전달해야 한다.

기존 coupled-stage 연구의 62개 검사, 51개 설정의 로컬 실험, fallback 및 작업자 수에 관한 부정적 결과는 다시 실행하지 않고 그대로 재사용했다. 이번 실험은 새 explicit 경로와 그 의존성에 한정된다. 원래 worktree를 보존하고 별도 연구 브랜치에서 작업했다. 조사한 파일·해시·발견 사항은 [INTAKE.json](INTAKE.json), [AUDIT_KO.md](AUDIT_KO.md)에 있다.

| 구성 요소 | 변경 내용 | 현재 범위 |
|---|---|---|
| `dopri5.rs` | RHS 전용 7단계 5(4), 직접 오차 합산, FSAL, 재사용 작업공간 | Jacobian/JVP/행렬/Newton 호출 없음 |
| `explicit.rs` | `Dopri5::solve`, `solve_observed`, 전용 결과·통계 | 비자율 RHS, vector atol, 실패 시 마지막 수락 상태 |
| `explicit_ensemble.rs` | 재사용 pool과 순서가 보존되는 독립 문제 실행 | 궤적별 별도 단계열·오차 제어·실패 |
| 기존 `Rodas5p` | 기본 알고리즘과 공개 의미 유지 | 강성 문제용 경로 계속 제공 |
| 실험 예제·Python 도구 | 전체 상태 저장, 독립 정확해 재계산, 설정별 raw 영수증 | 로컬 확장 비교 재실행 가능 |

전체 심볼 대응은 [API_MAP.json](API_MAP.json), 사용 예시는 [EXPLICIT.md](../../crates/vigilode/EXPLICIT.md)에 있다.

## 3. 수학적 근거와 실제 알고리즘

기울기 단계와 두 종점은 다음과 같다.

\[
K_i=f(t_n+c_i h,y_n+h\sum_{j<i}a_{ij}K_j),\qquad
 y_{n+1}=y_n+h\sum_i b_iK_i,\quad
 \widehat y_{n+1}=y_n+h\sum_i\widehat b_iK_i.
\]

주 방법은 5차, 내장 방법은 4차다. 비선형 차수 조건을 선형 시험 방정식만으로 대체하지 않고, 주 방법의 뿌리나무 조건 17개와 내장 방법의 8개를 정확한 유리수 연산으로 검산했다. `A1=c`, 마지막 행과 `b`의 동일성, 마지막 단계 시각도 함께 확인했다. 원 계수의 출처는 Dormand–Prince와 Hairer–Wanner 원본 코드이며, 이번 작업의 귀속과 실제 조회 범위는 [SOURCES.json](SOURCES.json)에 명시했다.

오차는 큰 두 상태를 다시 빼지 않고 `h Σ(b−bhat)K`로 직접 계산한다. 내장 차이가 일반적으로 `O(h^5)`이므로 단계 제어의 지수는 `1/5`다. 분모는 `atol_i + rtol max(|y_old,i|, |y_new,i|)`이며, 제곱합을 스케일해 overflow를 피한다. 국소 RMS 수락은 성분별 또는 전역 참오차 보증과 다르다.

**조건부 전역 정확도.** 충분히 매끄럽고 Lipschitz인 고정 모델에서 모든 단계가 검증된 근방에 있고 최대 단계가 `H`라면,

\[
e_{n+1}\le(1+L_*h_n)e_n+Ch_n^6+\delta_n,
\quad
e_N\le e^{L_*(T-t_0)}\{e_0+C(T-t_0)H^5+\sum_n\delta_n\}.
\]

곱의 지수 상계와 `Σh_n^6 ≤ H^5(T−t0)`가 증명을 준다. 정확 초기값·정확 산술에서는 전역 5차다. 실제 계산에서는 반올림, 불완전한 RHS, 비매끄러운 모델 전환 및 공간 이산화 오차가 추가된다. 이 식은 stiff 파라미터와 무관한 전역 인증서가 아니다.

**보장되는 작업량 감소.** 일곱 번째 기울기는 수락 종점의 RHS와 같으므로 다음 시도의 첫 기울기로 재사용한다. 오차 거절 시에는 바뀌지 않은 시작점의 기울기를 유지한다. 모든 시도가 완전히 평가되고 모델이 고정된 경우, `M`번 시도의 RHS 수는 `1+6M`이다. 매번 일곱 평가를 새로 하는 구현의 `7M`보다 `M−1`회 적다. 실패한 callback은 실제 진입 횟수로 별도 계수한다. 이 보장은 같은 시도열의 RHS 작업량에 관한 것으로, 다른 방법과의 전체 시간 우위를 뜻하지 않는다.

준비된 시도의 비용은 `6 C_f(n)+O(n)`, 솔버 작업공간은 `O(n)`이다. 전체 상태 저장과 사용자 RHS 비용은 별도다. 정상 고정 단계의 무할당 계약을 검사했지만, API 결과·출력 저장까지 무할당이라고 주장하지 않는다.

```text
입력과 지원 기능을 검증한다.
시작 RHS와 한 번 할당한 작업공간을 준비한다.
각 시도에서 관측 시각과 종료 시각에 맞춰 h를 자른다.
2–7단계, 주 종점, 직접 오차 벡터를 계산한다.
오차 수락 시 상태·시각·FSAL을 함께 확정한다.
오차 거절 시 시작 상태·시각·첫 기울기를 보존한다.
명시적 recoverable 오류는 재시도하고, fatal/불완전 출력은 종료한다.
성공 여부, 마지막 수락 상태, 실제 작업량과 출력 상태를 반환한다.
```

전체 계수, 증명, 안정성 다항식, 병렬 후보의 정확 tableau는 [THEORY_KO.md](THEORY_KO.md)와 [SYMBOLIC_CHECK.json](SYMBOLIC_CHECK.json)에 수록했다.

## 4. 적대적 검토와 구현 검증

독립 검토는 수치식뿐 아니라 캐시 수명, callback 실패, 통계, 출력 상태와 병렬 실패 전파를 조사했다. 확인된 핵심 제약은 다음과 같다.

| 조사 항목 | 교정·검증 결과 | 남은 의미 |
|---|---|---|
| 기존 문제 생성자가 derivative provider를 요구함 | 새 RHS 전용 커널 진입점 추가 | 가짜 zero JVP를 사용하지 않음 |
| 잘못된 FSAL 재사용 | 수락 종점만 승격, 거절 후 시작점 보존, 새 공개 단일 단계는 fresh RHS | 모델은 적분 세션 동안 고정되어야 함 |
| 전체 허용오차가 0인 입력 | callback 이전 거절 검사 추가 | 양의 rtol과 0인 정지 성분은 정상 허용 |
| callback의 부분 쓰기·NaN·오류 | 실패 종류 및 attempted/completed 계수 검사 | 마지막 수락 상태를 반환 |
| ensemble 오차 희석 | 궤적별 제어기 분리 | 서로 다른 물리 성분의 RMS 기준은 별도 문제 |
| 병렬 결과·실패 순서 | 1/2 worker 상태·작업량 일치, 실제 callback overlap 검사 | 통과 자체는 속도 향상 증거가 아님 |
| facade와 kernel의 중복 초기화 | 정확성 문제는 없으나 O(n) 메모리 순회 중복 발견 | 후속 측정 후 한 번의 poison pass 제거 후보 |

고정 소스에서 커널·할당 검사 13개, 공개 API·ensemble 검사 12개, 총 **25개가 통과**했다. 추가로 벤치마크의 명시적 실행 136개에서 `RHS=6×attempts+members`, `FSAL=attempts−members`와 Jacobian/JVP/선형해법/Newton 계수 0을 저장된 계수로 재확인했다([WORK_COUNTER_REPLAY.json](evidence/WORK_COUNTER_REPLAY.json)). 비선형 5차 수렴, 비자율 문제, vector atol, FSAL 비용, 대표 가능한 시간, 실패 후 상태와 무할당 계약을 포함한다. 첫 실행의 소스 식별 차이를 별도 고지했고, 최종 검사 도중의 `rlib` 링크 오류는 생성된 관련 crate 캐시를 정리한 뒤 같은 소스에서 해소됐다. raw 로그는 삭제하지 않았다. 최종 근거는 `checks_v2/00.log`와 `checks_v3/01.log`다. 전체 workspace를 새로 검증했다는 의미는 아니다.

## 5. 벤치마크 설계와 실측

10개 문제군 × 3개 허용오차 × 3개 방법의 **90개 설정**, 준비 실행 90회와 측정 270회를 수행했다. main 캠페인은 259.665초에 종료했고, 360회 모두 solver 성공 및 독립 상태 재검산을 통과했다. 별도 ensemble 4개 설정의 16회 실행도 모두 통과했다. 재계산한 정확해와 저장된 정확해의 최대 정규화 차이는 1.388e-17이다.

환경은 Rust 1.94.1, measurement(opt3, LTO off, codegen-units16), CPU quota 8인 공유 로컬 컨테이너다. CPU affinity를 따로 고정하지 않았다. 작은 문제에는 analytic dense-fast RODAS, 4096차원에는 analytic JVP+GMRES 경로를 사용했다. 외부 비교는 설치된 SciPy 1.17.0의 Fortran VODE/DVODE wrapper를 사용했다. 설정별 3회 시간의 중앙값과 관측 최소·최대값을 보존했다.

주 지표는 다섯 관측 시각 전체 성분에서의 `max |y−y_exact| / max(1, |y_initial|, |y_exact|)`다. 이는 solver tolerance와 독립된 기준이며, 미소 물리 성분의 상대오차 또는 연속 시간 최대오차를 인증하지 않는다. 아래 표는 이 값이 `1e-6` 이하인 설정들 중 측정 중앙값이 가장 작은 설정을 방법마다 선택한 결과다. 제한된 tolerance 격자에서의 선택이며, 최적화된 연속 비용 곡선을 추정하지 않았다.

| 문제 | DOPRI5 (ms) | native RODAS (ms) | RODAS/DOPRI 시간비 | VODE (ms) |
|---|---:|---:|---:|---:|
| decay | 0.0704 | 0.6284 | 8.929 | 1.6485 |
| driven | 0.0795 | 0.5970 | 7.512 | 2.7713 |
| logistic | 0.0715 | 0.4925 | 6.886 | 1.4913 |
| harmonic | 0.2217 | 0.7448 | 3.359 | 5.3913 |
| rapid | 2.1724 | 5.9347 | 2.732 | 39.8947 |
| damped | 0.1603 | 0.8376 | 5.225 | 6.4880 |
| mixed-scales | 0.1247 | 0.3418 | 2.741 | 1.8840 |
| nonnormal | 0.0586 | 0.3888 | 6.632 | 2.7392 |
| large-vector | 17.3975 | 118.8842 | 6.833 | 8.4032 |
| stiff-control | 171.7047 | 0.6197 | 0.004 | 정확도 기준 미달 |

비강성 9개 문제군에서 새 경로의 중앙값이 native RODAS보다 2.73–8.93배 빨랐다. 그러나 일부 작은 문제의 시간 범위가 크게 겹치므로 이를 통계적으로 확정된 배수나 일반 하드웨어의 성능 보증으로 해석하지 않는다. 모든 설정별 원값과 시간비의 관측 범위는 [SUMMARY.json](evidence/local_bench/SUMMARY.json)에 있다.

![전체 상태 오차와 실행 시간 비교](evidence/local_bench/WORK_PRECISION.png)

**반대 결과와 정확도 한계.** 강성 대조군에서는 DOPRI5가 31,014번의 시도와 186,085회 RHS 평가를 필요로 했고, `1e-6` 기준에서 RODAS가 약 277배 빨랐다. 비강성이라는 이유로 모든 문제를 explicit 경로로 보내지 않는 선택 정책이 필요하다. 4096차원 문제에서는 VODE가 DOPRI5보다 약 2.07배(`1e-6`)와 1.89배(`1e-8`) 빨랐다. 새 방법이 모든 비교군을 이긴 것은 아니다.

더 엄격한 `1e-8` 기준에서 mixed-scales는 native RODAS가 약 1.26배 빨랐고, nonnormal은 약 1.04배의 시간비로 사실상 근접했다. 현재 시험한 최소 requested rtol `1e-8`에서도 harmonic/rapid의 DOPRI 실제 표본 오차는 각각 약 `3.28e-8`, `2.17e-7`이어서 이 기준의 비교에 포함할 수 없었다. 이는 더 작은 tolerance에서도 실패한다는 결론이 아니다. 총 40개 방법/오차 기준 조합 중 30개만 비교 가능했고, 10개는 현재 격자에서 양쪽의 정확도 적격 설정이 충분하지 않았다.

**외부 비교의 조건.** VODE의 Python/NumPy callback 비용을 포함하며, native 방법은 관측 시각에 실제 착지하고 VODE는 내부 보간을 사용할 수 있다. 강성 VODE arm은 Jacobian을 제공하지 않는 functional-iteration BDF 설정이므로 최적화된 VODE-BDF의 대표 성능으로 볼 수 없다. 작은 문제에서의 큰 VODE 시간비를 수학 알고리즘 자체의 우위로 해석하지 않았다. Diffsol의 TSIT45/BDF 등 소스와 Julia adapter는 저장소에 존재한다. 다만 새 vector-rate 문제군과 stdin JSON 규약에 맞는 검증된 adapter가 공급되지 않았고 Julia 실행 파일도 없어 이번에는 미실행이다. 기존 adapter의 재사용·확장 경로를 [COMPARATOR_INVENTORY.json](evidence/COMPARATOR_INVENTORY.json)에 명시했다.

**독립 궤적 병렬화.** 4096차원 문제 16개를 궤적별 제어기를 유지한 채 실행했다. 모든 worker 수와 반복에서 저장 상태와 작업량이 일치했다. 아래의 2를 넘는 중앙값 시간비는 캐시·스케줄링·변동을 포함한 관측이며 초선형 병렬 효율의 증명이 아니다.

## 6. 순차 루프의 벡터화·homotopy·병렬화

현재 단계 조합은 연속 배열을 사용한다. 준비된 기울기 벡터에 대한 성분별 연산은 독립이므로 컴파일러 벡터화의 대상이 된다. 특정 SIMD 명령 생성이나 그 속도비는 이번 실험에서 별도로 검증하지 않았다. 사용자 RHS 내부 병렬화와 ensemble pool을 중첩할 때에는 oversubscription을 피해야 한다.

사용자의 단계 병렬화 아이디어에는 구체적인 16단계 5(4) 후보를 구성했다. 시작 기울기를 각 단계의 predictor로 두고 동기 Picard 갱신을 네 번 수행하되, 이미 정확해진 접두부는 다시 계산하지 않는다. 단계 오차가 초기 `O(h)`에서 네 번의 Lipschitz 갱신을 거쳐 `O(h^5)`가 되므로, 종점의 추가 오차는 `O(h^6)`이고 주 방법의 5차를 유지한다. 실제 확장 tableau의 모든 차수 조건도 검산했다.

| 비교 | 현재 DOPRI5 | 병렬 반복 후보 |
|---|---:|---:|
| FSAL 준비 후 RHS 총 작업 | 6 | 15 |
| RHS 의존 깊이 | 6 | 5 |
| 최소 이상적 병렬 작업자 | 1 | 5 |
| 주/내장 차수 | 5/4 | 5/4 |
| 현재 구현·성능 측정 | 완료 | 미구현·미측정 |

같은 시도 수, 충분히 비싼 RHS, 무시 가능한 동기화라는 비용 모델에서만 이상적 속도비 `6/5`를 얻는다. 총 RHS 작업은 2.5배가 된다. 더욱이 후보의 안정성 다항식은 5차 Taylor 다항식으로 바뀌고, 원점 근처의 순허수축에서 증폭률이 1을 초과한다. 따라서 빠른 무감쇠 진동의 일반 가속 방법으로 도입하지 않았다. 감쇠된 고비용 RHS에 한정된 후속 후보로 남겼다. 이는 병렬화 전반에 대한 불가능성 주장이 아니다.

확산형 특수 문제에는 다른 구성적 결과가 있다. 대칭 음의 준정부호 `L`과 `σ(L)⊂[−ρ,0]`에서 `T_s(1+hL/s²)`는 `hρ≤2s²`일 때 2-norm 수축이다. 한 macro-step의 안정성 제한을 만족하는 작용 수가 Euler의 `O(hρ)`에서 `O(√(hρ))`로 줄어든다. 다만 이 간단한 구성은 1차이므로 동일 정확도의 복잡도 감소로 바꿔 말할 수 없다. 고차 RKC/ROCK 또는 Laguerre 계열 도입은 목표 안정 영역·차수·오차 추정식·비정규성을 먼저 정한 뒤 비교해야 한다.

## 7. 정확도·속도를 위한 다음 개발 단계

[다음 작업의 기계 판독 목록](NEXT_STEPS.json)은 기존 18개 항목의 상태·의존성을 보존하고 새 10개 항목을 추가한다. 이전 작업을 완료된 것으로 일괄 변경하지 않았다. 우선순위는 다음과 같다.

1. **물리 변수 기준의 정확도 계약.** 축약 30변수 client의 상태와 오차를 33물리 변수로 lift하고, 해당 스케일에서 수락을 판정한다. 비선형 lift라면 tangent 근사 나머지까지 오차 예산에 포함한다. 비강성 선택만으로 이 정확도 의무가 사라지지 않는다.
2. **연속 출력과 사건 위치 추적.** 관측점이 많을 때 매번 단계 종점을 맞추는 비용을 줄이는 직접적인 방법이다. DOPRI의 적절한 dense extension과 시간 구간 검사, 독립 event root bracket 및 오차 검증이 필요하다. 현재 주 공식의 5차와 dense 출력 차수는 별도다.
3. **메모리 순회 최적화.** facade/kernel의 중복 NaN 초기화와 finite scan을 분석하고, malformed callback 검출을 유지하면서 중복 순회를 줄인다. n=4096/16384의 같은 참오차·작업량에서 효과를 판정한다. SIMD/FMA는 실제 생성 코드와 정확도 차이를 확인한 뒤 채택한다.
4. **비용을 측정하는 명시/암묵 전환.** 수락 상태에서만 전환하고, 제한된 probe·히스테리시스·최소 체류 시간·FSAL 무효화를 적용한다. 강성 secant 통계는 진단으로 사용하고 인증서로 취급하지 않는다. 전환 비용과 실패 회복을 포함한 work–precision에서 이득을 확인한다.
5. **장시간 진동과 높은 정확도.** 현재의 짧은 관측 표본을 넘어 위상·진폭 drift와 허용오차별 비용을 측정한다. DOP853·보존 구조를 이용하는 특수 방법은 별도 개발 후보이며 현재 구현이 아니다.
6. **비싼 RHS의 단계 병렬 후보와 확산 특수화.** 네 번 반복한 후보는 감쇠 문제에서 동일 정확도의 1/2/4/8-worker 비용을 먼저 측정한다. 총 작업 증가를 상쇄하지 못하면 기본 경로에 넣지 않는다. 안정화 다항식은 실수 음의 스펙트럼 문제군에서 정확도와 안정성 이득을 함께 확인한다.
