# 비강성 explicit 경로의 병렬화와 벡터화

이번 이식은 독립 초기값 문제를 병렬로 적분하는 `Dopri5Ensemble`을 제공한다. 한 번 만든 지역 thread pool을 여러 batch에서 재사용하고, 각 문제는 자신의 시간간격·허용오차·오차 제어 상태·실패 기록을 가진다. 결과 벡터는 입력 순서를 보존한다. 잘못된 초기값이나 callback 실패도 해당 원소에 남으므로 한 문제의 실패가 다른 문제의 실행을 취소하지 않는다.

## 1. 오차 제어와 병렬 스케줄링의 분리

문제 \(k\)의 차원을 \(n_k\), embedded 오차를 \(e^{(k)}\), 성분별 scale을 \(d_i^{(k)}\)라 하면 각 적분기는

\[
 E_k=\left[\frac{1}{n_k}\sum_{i=1}^{n_k}
 \left(\frac{e_i^{(k)}}{d_i^{(k)}}\right)^2\right]^{1/2}
\]

를 독립적으로 검사한다. 전체 ensemble을 하나의 큰 상태로 합쳐 \(\sum_k n_k\)로 나누면, 한 문제의 큰 오차가 다른 문제의 작은 오차에 의해 희석될 수 있다. 현재 구현은 이 결합을 만들지 않는다. RHS가 같은 입력에 대해 결정적이고 외부 모델을 실행 도중 바꾸지 않으면, 병렬 스케줄은 각 문제의 산술 순서와 수락·거절을 바꾸지 않는다. 따라서 순차 실행과 병렬 실행은 각 문제별 결과·작업량을 그대로 비교할 수 있다.

총 작업량이 \(W=\sum_k W_k\), 가장 비싼 문제의 작업량이 \(W_{\max}\)라면, 이상적인 \(P\)-worker 실행의 하한은 \(\max(W/P,W_{\max})\)이다. 실제 시간에는 작업 배치, 메모리 대역폭과 callback 동기화 비용이 추가된다. 이 관계는 독립 문제 수가 적거나 한 문제가 유난히 비쌀 때의 확장성 한계를 설명한다. pool을 batch마다 반복 생성하는 비용은 재사용 API로 제거한다.

구현은 기존 `rodas5p_integrators::ParallelExecution`의 indexed map을 사용한다. map의 바깥 결과는 항상 성공으로 반환하고, 각 ODE의 `Result`를 안쪽 값으로 저장하여 조기 취소를 막는다. 새 explicit solver 내부에는 추가 thread pool이 없다. 사용자가 자신의 RHS 안에서 만든 병렬 실행은 별도의 자원 정책이다.

## 2. 단일 궤적의 상태 벡터 연산

DOPRI5의 각 단계는 이미 계산된 기울기 벡터의 선형 결합과 한 번의 RHS 평가로 구성된다. 상태 성분에 대한 연속 슬라이스 루프는 compiler의 자동 벡터화와 SIMD에 적합하다. 그러나 RHS의 성분 간 결합, 분기, 메모리 접근, 별칭 정보와 compiler 선택에 따라 실제 벡터화가 달라진다. 현재 구현은 별도의 SIMD 명령집합을 전제하지 않으며, 특정 CPU의 벡터화 속도 향상은 실행 자료로 평가해야 한다. 여러 독립 궤적을 구조체 배열 대신 성분별 배열로 배치하는 추가 backend는 공유 시간간격이 적합한 경우에 따로 설계할 수 있다.

## 3. Explicit 단계와 homotopy 반복의 비용

Explicit Runge–Kutta의 단계 방정식은 엄격 하삼각 의존성을 가진다. 모든 단계를 이전 sweep 값으로 동시에 평가하는 Jacobi/Picard 구성은 원래 단계 해를 유한 sweep 안에 재현할 수 있다. 자세한 유도와 DOPRI5 계수 검산은 `THEORY_KO.md`에 연결한다. 이 구성의 평가는 단계 수만큼의 동시 RHS를 반복하므로 총 RHS 작업량과 저장량이 증가한다. 특정 RHS의 높은 지연시간, 사용 가능한 병렬 장치, 다수 초기 추정값의 재사용 등이 이 증가를 보상하는지는 별도로 측정해야 한다.

현재 production 방향의 코드에는 순차 DOPRI5 단계와 FSAL 재사용을 유지하고, 명확히 독립인 초기값 문제를 병렬 배치한다. 연구상 단계 동시 반복과 실제 시간을 따라가는 다중 초기값 문제 병렬화는 다른 알고리즘이다. 이 선택은 비강성 적분에서 Jacobian·행렬·Newton 계산을 제거하면서, 불필요한 RHS 반복을 추가하지 않는 직접적인 비용 절감 경로를 제공한다.

## 4. 구현 검증의 범위

`explicit_ensemble_contracts.rs`는 다음 계약을 검사한다. 실행 결과는 통합 테스트 영수증에서 확인한다.

- 서로 다른 초기값·시간구간·허용오차를 가진 문제들의 개별 실행, 1-worker ensemble, 2-worker ensemble, 같은 pool 재사용 간 결과 비트와 작업량 일치.
- 입력 거절, 실행 중 부분 실패, 정상 완료가 한 batch에서 모두 보존되고 입력 순서에 대응함.
- 두 첫 RHS 호출이 barrier에서 실제로 겹치는지 확인하여 실행 병렬성을 검사함. 이 검사는 시간 가속 비율을 측정하지 않는다.
- 0-worker 요청 거절과 빈 batch의 정상 처리.

이 테스트는 독립 궤적의 의미와 실제 동시 실행을 검증한다. throughput 향상은 별도의 로컬 benchmark에서 문제 수·차원·RHS 비용·worker 수를 기록하여 판단한다.
