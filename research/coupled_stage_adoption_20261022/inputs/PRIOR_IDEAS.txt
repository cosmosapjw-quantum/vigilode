**통합의 중심은 “matrix-free 연산자 세션 + 전체 stage 방정식의 동시 풀이 + 적응적 homotopy + 공통 오차·작업 예산”으로 잡는 것이 가장 유망해.** 중요한 것은 8개의 순차 stage에 스레드를 붙이는 것이 아니라, **같은 stage target의 해를 공유 부분공간과 병렬 보정으로 얻도록 실행 알고리즘을 바꾸는 것**이야. 이번에는 그 구성을 실제 경량 프로토타입으로 만들었고, 가능한 경우와 실패하기 쉬운 경우를 함께 확인했어.

## 2. 병렬 Rosenbrock와 homotopy를 연결할 수학적 중심

우선 autonomous·identity-mass 문제

\[
\dot y=f(y),\qquad J_0=f'(y_n)
\]

를 생각하자. 한 macro-attempt 안에서 \(J_0\)와 \(h\)를 고정하고, raw transformed stage 변수 \(U_i\)를 사용하면 현재 coefficient snapshot의 target은

\[
W U_i
=
h\gamma f\!\left(y_n+\sum_{j<i}A_{ij}U_j\right)
+\gamma\sum_{j<i}C_{ij}U_j,
\qquad
W=I-h\gamma J_0
\]

로 쓸 수 있어. 여기서 \(A,C\)는 엄격한 하삼각 행렬이야. 이 raw-\(U\) target과 native-\(K\) target의 부동소수점 차이는 저장소의 `raw_stage_target.rs`가 별도로 관리하고 있어. 

선형 부분과 비선형 remainder를 분리하면

\[
f(y_n+x)=f_0+J_0x+N(x)
\]

이고, 전체 stage 방정식은

\[
F(U)=(D-B)U-b-h\gamma R(U)=0
\]

가 돼. 여기서

\[
D=I_s\otimes W,\qquad
B=\gamma C\otimes I+h\gamma A\otimes J_0,
\]

\[
b=\mathbf1_s\otimes(h\gamma f_0),\qquad
R_i(U)=N\!\left(\sum_{j<i}A_{ij}U_j\right),
\qquad s=8.
\]

이에 대한 통합 homotopy를

\[
H(U,\lambda;\theta)
=
[D-\eta(\lambda)B]U-b-\lambda h\gamma R(U),
\]

\[
\eta(\lambda)=\theta+\lambda(1-\theta)
\]

로 놓을 수 있어.

**\(\theta=0\)**은 decoupled stage에서 출발하는 저렴한 seed이고, **\(\theta=1\)**은 affine stage coupling을 먼저 처리한 뒤 nonlinear remainder만 켜는 경로야. 어느 쪽이든 \(\lambda=1\)에서는 같은 원래 target으로 돌아와.

### 이번에 정리한 중요한 성질: 이 stage homotopy에서는 fold보다 보정 비용이 핵심이야

\(R_i\)는 이전 stage 변수에만 의존하므로 \(H_U\)는 block-lower-triangular이고, 대각 block은 모두 \(W\)야. 따라서

\[
\boxed{\det H_U(U,\lambda;\theta)=\det(W)^s}.
\]

즉 **고정된 \(W\)가 가역이고 필요한 stage 상태들이 유효 domain 안에 있다면, \(\lambda\)나 \(U\) 변화만으로 이 stage-root 경로에 fold가 생기지는 않아.**

이것은 condition number나 path curvature가 작다는 뜻이 아니야. Domain 이탈, overflow, \(W\)의 특이성은 여전히 가능하고, 별도의 물리적 equilibrium root 문제에는 적용되지 않아. 하지만 이 구조에서는 일반적인 다중근 추적용 pseudo-arclength를 먼저 붙이기보다 다음에 집중하는 편이 적절해.

**좋은 affine/history seed를 만들고, 적은 수의 병렬 보정으로 \(\lambda=1\) target에 도달하며, 그 출력 오차를 검증하는 것.**

정확한 continuation tangent는

\[
H_U\frac{dU}{d\lambda}
=
(1-\theta)BU+h\gamma R(U)
\]

를 만족해. 기존 코드의 truncated partial-linear inverse를 사용하는 predictor는 이 tangent의 저렴한 근사로 해석해야 하고, nonlinear derivative까지 포함한 정확한 tangent로 자동 해석하면 안 돼. 최종 target 검사가 중요한 이유야.  

## 3. “8 sequential loop가 아닌” 실제 후보를 만들었어

내가 가장 먼저 구현할 것을 권하는 구조는 다음이야.

\[
\boxed{
\text{공유 JVP 부분공간}
\;\longrightarrow\;
\text{작은 coupled-stage predictor}
\;\longrightarrow\;
\text{동시 stage RHS/JVP}
\;\longrightarrow\;
\text{homotopy/Newton 보정}
}
\]

구체적으로 \(V_m\)을 JVP로 구성하고

\[
U\approx (I_s\otimes V_m)z
\]

로 표현해. 그러면 큰 공간에서 stage마다 별도의 \(W\)-solve를 하는 대신, **\(sm\) 차원의 작은 전체 stage 문제**를 풀 수 있어. 이후에는 반드시 원래 공간에서 residual을 확인하고, 부족한 방향이 있으면 부분공간을 확장해야 해.

### 실제 프로토타입 결과

세 spectral group을 갖는 합성 quadratic 문제에서 다음을 실행했어.

| 항목 | 결과 |
|---|---:|
| 원래 상태 차원 | **12,288** |
| JVP로 생성한 부분공간 차원 | **3** |
| 작은 전체 stage 시스템 차원 | **24** |
| 관측된 동시 stage 작업 수 | **4** |
| \(\lambda=1\) 직접 보정의 작은 Newton solve | **2회** |
| stage 평가 batch | **3회** |
| 원래 공간의 상대 stage residual | **\(6.64\times10^{-15}\)** |
| 순차 stage-root 기준 출력 차이 | **WRMS \(1.28\times10^{-8}\)** |

이 후보는 **원래 공간의 \(n\times n\) Jacobian이나 \(W\)를 구성하지 않았고, 후보 계산에서 8회의 큰 순차 \(W\)-solve도 하지 않았어.** 여기서 순차 stage 해는 결과 검증에만 사용했어. 구현과 전체 기록은 패키지의 `projected_parallel.py`, `projected_parallel.json`에 있어.

다만 이 결과를 과장하지 않도록 두 가지를 분명히 했어.

첫째, 전체 계산이 JVP 3회로 끝난 것은 아니야. **3회는 basis 생성용 base-JVP 수**이고, 별도로 projected stage derivative 작업 72 vector-equivalents, RHS 24 stage-vectors, full residual 검사가 있어.

둘째, 이것은 작은 불변 부분공간이 존재하는 **합성 대조군**이야. 범용 비선형 PDE나 native Rust 적분기의 전체 wall-time 우위를 증명하지는 않아. 그렇지만 네가 원하는 세 기능을 함께 사용하는 실행 구성이 단순한 개념도가 아니라 **실제로 구성 가능함을 보여주는 출발점**은 됐어.

### 낮은 RHS rank만으로 이 경로를 고르면 안 돼

별도 대조에서는 두 문제 모두 affine stage RHS의 rank가 1이었어.

| 문제 | 사용한 basis 차원 | 출력 WRMS |
|---|---:|---:|
| 세 eigenvalue group, 384변수 | **3** | \(2.29\times10^{-8}\) |
| 넓은 diagonal spectrum, 64변수 | **32** | **1.482** |

두 번째 문제는 상대 stage residual이 약 \(2.42\times10^{-9}\)였지만, 출력 기준 1을 넘었어. 따라서

\[
\text{낮은 RHS rank}
\;\not\Rightarrow\;
\text{작은 Krylov 차원}
\]

이고,

\[
\text{작은 상대 residual}
\;\not\Rightarrow\;
\text{요청 출력오차 충족}
\]

이야. `rhs_telemetry`의 rank·방향성 정보는 좋은 **후보 선택 신호**지만, 승인 조건 자체가 되어서는 안 돼. 그 모듈도 현재 추천을 advisory로 구분하고 있어. 

## 4. 좌표·homotopy·전처리를 따로 최적화하면 안 되는 이유

### Stage 좌표에 따라 반복의 난도가 크게 달라져

같은 RODAS5P target이라도 raw-\(U\)의 단순 diagonal splitting에는 \(\gamma C\)라는 결합이 남아. 반면 \(K\) 표현의 선형 결합은 \(hL\otimes J_0\) 형태야.

독립적으로 계수를 변환해 비교한 scalar \(z=hJ_0=-0.01\) 대조에서는

\[
\|T_U\|_\infty \simeq 68.676,
\qquad
\|T_K\|_\infty \simeq 0.07838
\]

이었어. 따라서 **raw-\(U\)에서 단순 병렬 Picard가 나쁘다는 결과를 모든 stage 표현의 본질적인 장애로 해석하면 안 돼.**

반대로 stiffness가 커지면 \(K\) 표현도 자동으로 수축하지 않아. 각 norm은 좌표에 의존하므로 최종 판단은 반드시 같은 원래 출력에 대한 오차로 해야 해. 이 비교는 native faer coefficient bits를 그대로 재현한 것이 아니므로, 실제 통합에는 target 변환 allowance가 필요해.

저장소에는 이미 static stage-coordinate 후보를 만든 뒤 원래 target으로 되돌려 검사하는 `stage_chart_candidate`가 있어. 이 원칙을 재사용하는 것이 좋아. **차트에서 residual이 작다는 이유로 승인하지 않고, 복원한 stage를 원래 target에서 승인하는 구조**야. 

### Homotopy 구간을 많이 나누는 것이 항상 유리하지 않아

앞의 12,288변수 프로토타입에서 비교하면 다음과 같아.

| 경로 | 작은 Newton solve | stage batch | stage derivative vector-equivalents |
|---|---:|---:|---:|
| affine seed에서 \(\lambda=1\) 직접 보정 | **2** | **3** | **72** |
| \(\lambda=0.25,0.5,0.75,1\)을 차례로 진행 | 6 | 10 | 240 |

두 경로 모두 충분히 정확한 같은 stage root에 도달했지만, 쉬운 문제에서는 여러 continuation 구간이 불필요한 일을 추가했어.

따라서 권장 정책은 **homotopy를 사용하지 않는 것**이 아니라,

> 좋은 predictor로 \(\lambda=1\)을 먼저 시도하고, 필요한 경우에만 continuation의 해상도를 높이는 것

이야. 매번 네 개의 path point를 의무적으로 거치는 방식은 피하는 편이 좋아.

### Krylov 반복 감소도 전체 비용 감소와 같지 않아

작은 quadratic 대조에서 같은 affine seed를 사용했을 때,

| 전처리 깊이 | Outer 보정 | Krylov 반복 합 | \(W^{-1}\) batch 적용 |
|---|---:|---:|---:|
| \(q=0\) | 2 | 13 | **17** |
| \(q=1\) | 2 | **7** | 22 |

였어. \(q=1\)은 inner 반복을 줄였지만, 전처리 자체가 더 비싸서 \(W^{-1}\) 적용은 늘었어. 이 대조에서는 affine seed를 참조용으로 계산했으므로 전체 solver 속도비를 주장하지 않았고, **보정 단계 내부의 작업량 비교**로만 사용했어.

통합 policy는 `iteration_count` 하나가 아니라

\[
C_{\mathrm{RHS}}
+C_{\mathrm{JVP}}
+C_{W^{-1}}
+C_{\mathrm{orthogonalization}}
+C_{\mathrm{synchronization}}
+C_{\mathrm{validation}}
\]

를 봐야 해.

## 5. 상황별로 어떤 조합을 선택할 것인가

현재 근거에 비추어 다음처럼 나누는 것이 타당해. 이 표는 검증 없이 고정할 dimension threshold가 아니라 **실제 선택 policy의 구조**야.

| 관측되는 상황 | 우선 후보 | 승인 전 확인할 것 |
|---|---|---|
| JVP가 가능하고 유효 Krylov 부분공간이 작음 | **공유 부분공간 + coupled-stage homotopy** | 원래 공간 residual, basis 밖 nonlinear remainder, 출력오차 전달 |
| 부분공간이 크지만 stage 작업이 충분히 무겁고 독립 실행 가능 | **전체 stage Newton–Krylov + 병렬 common-\(W\) batch** | 총 \(W^{-1}\)/JVP 비용, 병렬 critical path, 전처리 비용 |
| 약한 국소 stiffness·작은 nonlinear coupling | **적절한 \(K\)-chart + 저차 보정** | 적은 round로 같은 출력오차를 달성하는지 |
| 선형 stiffness·oscillation이 지배하고 \(\varphi\)-action이 경제적 | **parallel exponential Rosenbrock 후보** | \(\varphi\) 근사, embedded/dense error, 실제 switching 오차 |
| 메모리 지배 stencil·싼 RHS | **batched JVP·벡터화·공유 방향 감소 우선** | 단순 stage threading보다 실제 대역폭 사용이 개선되는지 |
| 작은 문제·저렴한 direct solve·병렬 후보의 예산 실패 | **기존 sequential/direct/banded 보호 경로** | fallback 비용까지 포함한 총경제성 |

Parallel exponential Rosenbrock와 parallel peer/W 방법은 문헌상 실제 stage 병렬성을 갖는 별도 방법군이야. 특히 parallel exponential Rosenbrock는 높은 차수를 적은 병렬 의존 단계로 구현하도록 설계된 방법을 제공해. 다만 이는 기존 RODAS5P의 순서를 바꾸는 것과는 달라서, 방법 전환과 오차 계약을 독립적으로 검증해야 해. 프로젝트의 기존 exponential 후보를 이 관점에서 활용하면 돼. [ScienceDirect](https://www.sciencedirect.com/science/article/pii/S0898122116300165)

### Matrix-free와 preconditioner를 혼동하지 않는 것이 중요해

`matrix-free`는 곧 `preconditioner-free`가 아니야. **현재 target의 Jacobian action은 JVP로 유지하면서, 별도의 근사 전처리기를 사용하는 방식**은 정당한 구성이고 PETSc도 이를 명시적으로 구분해. 다만 strict no-assembly를 요구하는 모드와 sparse/block 전처리기를 허용하는 모드는 사용자 계약에서 구별해야 해. [PETSc](https://petsc.org/release/manual/snes/)

오래된 LU나 근사 선형화를 **현재 \(W\)의 정확한 solve로 재사용하는 것**과 **현재 \(W\)를 푸는 데 도움을 주는 preconditioner로 사용하는 것**도 달라. 후자는 가능하지만, residual은 반드시 현재 연산자로 계산해야 해.

그리고 preconditioner가 iteration 중 바뀌거나 내부 iterative solve 때문에 비선형 작용이 되면 일반 GMRES의 가정과 어긋날 수 있어. 이 경우 flexible GMRES 같은 구조가 필요해. [PETSc](https://petsc.org/release/manualpages/KSP/KSPFGMRES/)

## 6. 실제 병렬 성능은 별도로 선택해야 해

이번에는 thread overlap만 확인하지 않고, **8개 stage의 reaction–diffusion RHS kernel**을 실제로 1·2·4 workers로 실행했어. 결과 bits는 같았지만, 작거나 중간 크기의 kernel에서는 threading이 오히려 느렸어.

| Stage당 변수 수 | 1 worker | 2 workers | 4 workers |
|---:|---:|---:|---:|
| 256 | **0.139 ms** | 0.358 ms | 0.506 ms |
| 16,384 | **0.522 ms** | 1.175 ms | 1.694 ms |
| 131,072 | 3.645 ms | **3.322 ms** | 3.396 ms |

가장 큰 사례도 paired 시간비의 중앙값은 2 workers에서 약 1.048, 4 workers에서 약 1.017이었고, 개별 블록에서는 이득과 손해가 모두 있었어. 이것은 Python/NumPy·공유 환경의 **kernel 실험**이므로 native Rayon의 crossover로 가져가면 안 돼.

그럼에도 설계에 주는 결론은 분명해.

**“8개가 병렬 가능하니 8개를 동시에 실행한다”가 아니라, 같은 수학적 batch를 어떤 방식으로 실행할지 따로 선택해야 해.**

우선순위는 preallocated stage storage, component-major 또는 적절한 SoA 배치, 여러 방향을 한 번에 처리하는 `JVP_batch`, 그리고 제한된 thread budget이야. 작은 문제는 한 스레드에서 batch/vectorization으로 처리하고, 큰 문제는 stage 병렬성과 공간 병렬성을 경쟁시켜야 해. 기존 README도 synthetic parallel probe가 memory-bound JVP scaling을 예측하지 못한다고 명시하고 있어. 

## 7. 정확도와 비용의 승인 기준

### Root residual 하나로 승인하면 안 돼

이 통합에서 분리해야 할 오차는 적어도 다음과 같아.

\[
\varepsilon_{\mathrm{total}}
\;\leftarrow\;
\varepsilon_{\mathrm{time}}
+\varepsilon_{\mathrm{stage}}
+\varepsilon_{\mathrm{linear}}
+\varepsilon_{\mathrm{JVP}}
+\varepsilon_{\mathrm{projection}}
+\varepsilon_{\mathrm{target\ conversion}}
+\varepsilon_{\mathrm{dense}}.
\]

이것은 무조건 단순 합이 엄밀한 상계라는 뜻이 아니라, **각 오차의 정의·단위·전달 연산자를 먼저 분리해야 한다**는 뜻이야.

stage error에 대해 유효한 inverse/derivative bound가 있다면

\[
E_i\le a_i+\sum_{j<i}L_{ij}E_j
\]

라는 causal bound를 구성할 수 있고,

\[
E\le (I-L)^{-1}a
=\sum_{k=0}^{s-1}L^k a
\]

로 전달할 수 있어. \(L\)이 strictly lower라서, 전역적인 \(\|L\|<1\)을 반드시 요구할 필요는 없어. 하지만 bound를 만든 상태 영역이 실제로 닫히는지, 그리고 endpoint뿐 아니라 embedded·dense-output weights까지 전달했는지는 확인해야 해. 저장소의 `causal_majorant`가 이미 이 방향을 제공하고 있어. 

또한 현재 코드가 강조하듯이 **Newton correction 한 번의 출력 투영은 일반적인 nonlinear error bound가 아니야.** witness가 없는 범용 문제와 실제 outward certificate가 가능한 문제를 같은 승인 등급으로 처리하면 안 돼.  

Inner solve도 처음부터 끝까지 동일한 극소 tolerance로 풀지 않는 편이 좋아. 비선형 iteration의 진행과 최종 출력 예산에 맞춰 forcing을 조절하는 원칙은 inexact Newton 문헌에서 뒷받침돼. 다만 그 자체로 시간적분의 전역오차를 보장하는 것은 아니야. [SIAM](https://epubs.siam.org/doi/abs/10.1137/0917003)

### Fallback을 포함해서 이익이어야 해

같은 \(h\)와 출력 계약에서 후보 비용을 \(C_a\), 검증 비용을 \(C_v\), fallback 비용을 \(C_f\), 후보 승인 확률을 \(p\)라고 하면, 공유 작업을 재사용하지 않는 단순 모델은

\[
\mathbb E[C]
=
C_a+C_v+(1-p)C_f.
\]

따라서 후보가 경제적이려면

\[
\boxed{p>\frac{C_a+C_v}{C_f}}
\]

여야 해.

이 식은 왜 “좋은 경우에는 빠르다”만으로 부족한지 보여 줘. 작은 비용의 성공 경로라도, 어려운 step마다 homotopy를 끝까지 수행하고 다시 순차 경로를 실행하면 전체적으로 손해일 수 있어.

실제 selector는 이보다 더 나아가 **승인된 물리적 시간 전진량당 비용**을 최소화해야 해. 서로 다른 \(h\)를 사용하는 후보의 step당 시간만 비교하면 안 돼.

## 8. 다음에 연결할 구현 단위는 하나로 좁히는 것이 좋아

지금 가장 먼저 필요한 것은 기능별 옵션을 더 늘리는 일이 아니라, 아래 계약을 갖는 **하나의 완전한 coupled matrix-free step**이야.

```text
accepted state와 operator epoch 고정
    → JVP/common-W 세션 준비
    → stage chart 및 공유 부분공간 predictor 선택
    → lambda=1의 병렬 corrector 우선 시도
    → 필요한 경우에만 q·lambda·basis 확대
    → 원래 target의 residual·출력·embedded/dense 오차 검사
    → 성공: state/controller/history commit
    → 실패: 사용한 작업을 보존하고 보호 경로로 rollback/fallback
```

구현상으로는 다음 네 경계를 명확히 하면 돼.

**`StageTargetContract`**가 raw-\(U\)/native-\(K\), coefficient identity와 출력 변환을 소유하고, **`OperatorSession`**이 현재 \(W\), 전처리기, 공유 basis와 worker별 workspace를 소유해. **`StageRootDriver`**는 predictor·homotopy·보정 깊이만 결정하고, **`CommitGate`**가 물리적 step과 출력의 승인을 담당하는 구조야. 실행 방식은 이들과 별도의 `StageExecutionPlan`에서 선택하면 돼.

이렇게 해야 homotopy가 특정 dense-LU 구현에 종속되지 않고, matrix-free backend를 바꿀 때마다 root 방정식이나 오차 의미까지 달라지는 문제를 피할 수 있어.

**이번 연구의 우선순위 판정은 다음과 같아.**

- **최우선:** 공유 JVP 부분공간과 실제 병렬 common-\(W\)를 연결한 coupled-stage homotopy.
- **동시에 필요한 것:** stage 좌표·전체 출력오차 전달·총작업 예산.
- **조건부 대안:** 부분공간이 커질 때의 full-space stage Newton–Krylov, oscillatory/semilinear 구간의 parallel exponential 후보.
- **유지할 보호 장치:** 기존 sequential/direct/banded 경로. 다만 이것을 본래의 병렬·matrix-free 연구 목표 대신으로 삼지는 않음.

이번에는 **30개 homotopy 대조 설정, 실제 병렬 부분공간 프로토타입 2개, 108개 kernel timing 기록과 13개 검증 테스트**를 실행했어. 테스트는 모두 통과했지만, 이것은 **통합 아이디어와 경량 구현의 검증**이야. Native Rust 통합, 전체 trajectory 차수·연속 출력오차, 실제 방법 전환, 다양한 물리 client에서의 최적 정책은 아직 검증하지 않았어.

결론적으로, **네가 원하는 세 축을 결합하는 방향은 타당하고, 실제로 큰 공간의 8회 순차 solve를 피하는 구성도 만들 수 있었어.** 다만 그 이점을 얻는 핵심은 “모든 기능을 켜기”가 아니라 **작은 부분공간·좋은 stage 좌표·필요한 만큼의 homotopy 보정·실제 하드웨어 비용을 함께 선택하는 것**이야.
