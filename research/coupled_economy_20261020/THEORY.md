# Residual-first evaluation and bounded speculative work

No Rosenbrock coefficient, projected equation, accepted residual threshold, or embedded error formula changes in this node. At an iterate z_k of a fixed projected stage equation H(z,lambda)=0, the eager path forms r_k=H(z_k) and A_k=dH/dz(z_k) before deciding whether r_k already meets its convergence test. The new path first forms the same r_k from the same saved stage states. If the identical residual test accepts, A_k is not used and is not computed. If the update budget is exhausted, A_k is also not needed. Otherwise the same derivative A_k, same small solve A_k delta=-r_k, and same z_{k+1}=z_k+delta are computed in the same accumulation order.

Under pure deterministic callbacks at a frozen model epoch and the same floating-point environment, this is a scheduling change, not a quasi-Newton or lagged-Jacobian method. An induction through accepted updates gives identical z, original-space stages, embedded error and final full-space residual. The implementation checks epoch boundaries and tests bits; callback invocation order differs and deliberately avoids requests for an unused derivative. A derivative callback that is invalid only at an unqueried state may cause the old eager path to fail while the new one need not fail. Therefore unconditional failure-identity for impure/invalid callbacks is not claimed. Full-space validation and its required JVPs are never skipped.

For basis dimension m and s=8, one terminal unused derivative costs8*m JVP vectors. The new ledger records actual JVP attempts separately from a counterfactual unused_stage_jvp_avoided count. Two parallel phases incur another dispatch and barrier on iterations needing an update. Saved JVP work is not automatically the same percentage of saved wall time. States are retained between phases, so no second RHS evaluation or changed rounding of the stage states is needed.

Candidate JVP caps reuse the existing fail-closed callback budget: effective_cap=min(caller_cap,explicit_cap). Reserve the whole next JVP batch before launching it. Budget exhaustion declines the candidate and leaves the existing sequential fallback available. The numerical target and error thresholds do not loosen. This cap is NOT a maximum time or maximum total work: RHS, basis projections, small dense solves and the fallback still cost work.64/256are fixed sensitivity cases, not trained optimal thresholds. A cap may reject a useful candidate; such failures and resulting cost must remain in the result table.

The reference discrepancy used in the benchmark is empirical and measures the frozen raw-U root, not exact ODE trajectory error. Candidate return remains separate from embedded physical timestep admission. No adaptive integration/commit state machine, certified residual-to-output transport or dense-output proof is claimed.
