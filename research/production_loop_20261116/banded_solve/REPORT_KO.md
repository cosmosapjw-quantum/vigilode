# V19·V21: banded stage solve kernel 결과 (loop L1)

이 문서는 `build_report.py`가 `RESULTS.json`과 `RESULTS_V21.json`에서 생성한다. 숫자는 모두 두 파일에서 읽는다.

용어: **stage pattern** = RODAS5P 시도 1회의 선형대수(분해 1회 + solve 8회). **A0** = 보호 client `BandedStageLu`(Indexed kernel, facade의 banded 경로가 쓰는 kernel). **cycles** = 고정 core에서 잰 user-mode CPU cycle. **instructions** = user-mode 명령어 수(결정적, 호스트 부하와 무관).

## 3. 의미와 남은 일

- 이 결과는 kernel과 시도 단위의 비용이다. 방법(RODAS5P tableau, controller, 허용오차)과 결과 bit는 그대로다.
- 기본 kernel을 바꾸는 것은 이 loop의 권한 밖이다(보호 파일, 기본 경로 불변). facade의 banded 경로를 Slices kernel로 바꿀지는 owner 결정 사항이다.
- cycle 판정이 NOT_DECIDABLE인 칸은 조용한 호스트에서 같은 명령으로 다시 재면 된다(재측정은 cell당 2회까지, 기록은 모두 보존).
- 탐색 기록(판정 아님): 같은 코드를 `-C target-cpu=x86-64-v3`로 build하면 Slices kernel의 명령어가 넓은 band 문제에서 다시 0.46-0.62배가 되고 상태 hash는 같다(`logs/xflag_v3_instructions.log`).
- 다음 병목: tight kernel 뒤에는 stage 산술(보호 driver의 선형결합 loop)과 RHS가 남는다. V04의 명령어 수로 보면 stage 산술은 성분·stage당 약 95개 명령어다. 이 부분은 보호 driver 안에 있어 client로는 바꿀 수 없다.
