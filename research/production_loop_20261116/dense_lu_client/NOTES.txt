== Design decisions so far ==
D1 (reuse arm). Client-owned faer Mat<f64> n x n for the combined factors, two usize arrays for the permutation,
   one MemBuffer for the transpositions, one Mat n x 1 and one MemBuffer for the solve. factor() writes
   W = -J (+ inv_h_gamma on the diagonal) straight into the column-major Mat and calls
   faer::linalg::lu::partial_pivoting::factor::lu_in_place(.., Par::Seq, .., Default::default()): the call,
   the parameters and the storage layout (a faer Mat of the same shape) of the protected path.
   The protected split into L and U is not repeated: both triangular solves read only their own triangle
   (see above), so the combined matrix is passed as L and as U. Identity is then tested, not assumed.
D2 (threaded arm). faer's own threads are behind the cargo feature "rayon", which the workspace manifest switches
   off; Par::Rayon does not exist in this build. Switching it on needs Cargo.toml:24 and Cargo.lock (new
   packages rayon -> faer, spindle): both protected. So the arm as the contract words it ("through a parallelism
   argument of the factorisation call") is NOT_RUN. To be confirmed with `cargo tree -e features` and a compile
   probe, both kept as logs.
   Candidate exploratory arm that needs no manifest change: the same recursion written in the client, with the
   triangular solve and the matmul of each level split over column chunks on a client-owned rayon pool (rayon is
   already a dependency of rodas5p-integrators). To be decided after the reuse arm is in place.
