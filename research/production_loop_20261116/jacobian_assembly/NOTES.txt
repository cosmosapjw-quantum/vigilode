DESIGN AS BUILT
- AssemblyStageClient = finite-difference engine + an unchanged back end of the kit. The engine writes the
  Jacobian into a shared slot in the layout of the back end (row-major n x n, or the BandedJacobianFn band
  layout); the back end reads it through its normal provider (DenseLuStageClient: jacobian_into of an internal
  view problem; BandedStageLu / BandedTightStageLu: the band fill callback). The provider refuses a request
  for another (t, y) than the assembled one. One copy of the Jacobian per linearization.
- Sequential dense build = fd.rs:476-509 statement for statement; sequential coloured build = fd.rs:581-622
  for the Curtis-Powell-Reid first-fit groups (for a full band: j mod (lower + upper + 1), the facade's
  groups).
- Threaded build: three parallel passes in one pool.install (right-hand sides into per-task slots that own
  their shifted state copy; entries per task; target by rows). No lock held during a right-hand side, no
  per-thread scratch (a right-hand side that itself uses rayon cannot deadlock the client).
- Failure order of the threaded build = the sequential one (first failing task in task order, base first);
  difference: every right-hand side of the build has been entered, so rhs_calls of a failed build is larger.
- Checks: every coloured build compares the rows a colour does not cover with the base evaluation (no extra
  right-hand side); first linearization (and on request) compares 8 evenly spread single-column evaluations
  made on the calling thread (+ the base evaluation again for threaded execution). Sequential dense route:
  no check (it is the facade's algorithm; nothing to compare with).
- Typed error AssemblyError (UncoveredRowChanged, UndeclaredEntry, AliasedEntry, NotReproducible, ...); the
  driver gets CoreError::InvalidInput (fatal), the typed error stays in AssemblyReportHandle.
