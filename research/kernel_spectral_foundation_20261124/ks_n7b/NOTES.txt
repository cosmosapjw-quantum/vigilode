0. Question
-----------
F5: a PairedReal run reports the client id vigilode-separable-fourier-stages-v1, like Complex,
and SeparableReport has no transform field. So a Solution cannot tell the two arms apart. Close
F5 first, then make BoxTransform::PairedReal the default. Complex stays selectable.

1. Where the run record of a separable solve comes from (code at 13d26475)
--------------------------------------------------------------------------
- crates/vigilode/src/solve.rs:499-532 builds the record. It creates
  report = SeparableReport::default() inside an Arc<Mutex<..>> and hands it to
  SeparableStages::client(report). After the driver returns, it copies the report into
  DriverWork::SeparableClient { jacobian_reuses, client, report } with
  client = SEPARABLE_STAGE_CLIENT_ID (solve.rs:530), a constant.
- StageLinearSystem (rodas5p-integrators src/client_stage.rs) has no identifier method, and the
  client that the driver returns is dropped (solve.rs:506, `_client`).
- So the SeparableReport is the only per-run value that separable.rs hands to a Solution. The
  client id is chosen in solve.rs, outside this task's paths (separable.rs, spatial.rs exports,
  tests/spatial_separable.rs, ks_n7b/**, results/KS_N7B_*.json).

2. Design choice (F5)
---------------------
(a) A second client id for the paired box solve. It does not break the API (one new pub const
    and a getter). But solve.rs:530 would have to write `stages.client_id()` instead of the
    constant, and solve.rs is outside the allowed paths. A constant cannot depend on the run.
    Not done.
(b) A field in SeparableReport. It is inside the allowed paths, but it breaks struct literals
    and exhaustive patterns of SeparableReport (all fields public, not non_exhaustive).
(c) Another record reachable from separable.rs alone: none. Stats, RouteRecord, Options and
    driver_message are written in solve.rs. WorkCounters hold counts, not labels.
Chosen: (b). SeparableReport gets `pub box_transform: Option<BoxTransform>`: Some(transform) on
the box, None on a sphere grid (its kernel always pairs rings and ignores the setting).
SeparableStages::client writes the field from the kernel it builds, before it hands that kernel
to the client, so the record cannot drift from the arithmetic that runs. BoxTransform derives
Serialize in kebab case ("complex", "paired-real", the names of Display and FromStr), so the
serialized run record carries the transform too.
Why (b) over (a):
- (a) cannot be done inside the allowed paths; (b) can.
- Decision KS-N7-T in RUN.json says "first records the transform in SeparableReport", and the
  protocol names the report first.
- The report is typed: an enum, not a string to parse.
- The client id keeps naming the client. Both transforms run in the same client with the same
  certificates.
Cost of (b): it is a semver-major change of SeparableReport (cargo-semver-checks lint
constructible_struct_adds_field). Downstream code breaks if it writes a struct literal that
lists all nine fields, or destructures the report exhaustively.
Scope of that cost:
- SeparableReport was added at a0ec98ba (SL-N5, 2026-11-25) on this research branch. It is not
  on main and was never released.
- The workspace has no struct literal and no exhaustive pattern of it (grep).
- Literals with `..Default::default()` still compile; the new field defaults to None.
Left to the orchestrator: if the non-breaking (a) is preferred, it needs a one-line change of
solve.rs:530, plus a const and a getter in separable.rs. It can be added to (b) or replace it.

3. Default change (a separate commit, after the record)
-------------------------------------------------------
- `#[default]` moves from BoxTransform::Complex to BoxTransform::PairedReal.
  DiffusionGrid::separable_stages uses BoxTransform::default(), so every box built without
  with_box_transform runs PairedReal. with_box_transform(BoxTransform::Complex), or
  "complex".parse(), selects Complex. Sphere grids are unaffected (they ignore the setting).
- Docs: module doc, BoxTransform and its variants, with_box_transform, separable_stages,
  SEPARABLE_STAGE_CLIENT_ID (both transforms run under it; the report tells them apart).
  F6 of the KS-N7 review: at 256x256 PairedReal holds 33,024 + 4,096 complex values against
  65,536 (0.57), not "half"; the variant doc states this.
- Consequences: default box runs change their bits within round-off. The KS-N7 agreement bound
  is ||x_p - x_c||_inf <= 1e-13 S/(z - c) per stage solve (K17). Step counts may differ in
  principle. inertia() and solve_stage() of a default box use the PairedReal kernel. Inertia
  counts do not depend on the transform: BoxKernel::crossings reads only the symbols.
