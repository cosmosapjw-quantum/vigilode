# 코딩 연구 루프 C1–C10

공통 정책을 적용하고 단계 이름·순서를 유지하라. 현재 의무에 필요한 단계부터 이어가라. 기존 검증은 입력·가정·구현·도구의 관련 identity가 유지되는 동안 재사용하라.

## C1 목표·baseline

입력·출력, 계산할 물리량, 가정·단위, 기준식·코드·데이터, 정확도·비용·완료 기준을 확인하라. 현재 branch·수정 상태·원본을 실제로 읽어라.
baseline의 정의·정규화·버전을 확인하고 오류가 명확하면 교정 근거와 과거 결과를 보존하라. 사용자 고정 허용오차·물리적 목표를 유지하라.
**산출물:** 식별 가능한 baseline과 입력·출력·수용 기준.

## C2 식–데이터–코드

이론식에서 계산식과 함수·자료구조·초기/경계조건까지 실제 경로를 따라가라. 호출자·저장 형식·단위 변환·정규화와 영향 범위를 확인하라.
원인을 이론, 수치해석, 구현, 환경, 권한/정책, 입력 의존성으로 분류하라. 추상적 비판은 해당 식·함수·데이터로 구체화하라.
**산출물:** 수정 위치, 의존성, 식–코드 대응.

## C3 수치 설계

연속식 → 근사/closure → 이산화 → 계산 순서 → 오차·안정성의 연결을 작성하라. 보존량·대칭·양성성·강성·경계·conditioning·극한 중 현재 주장에 필요한 항목을 다루라.
유용한 수학적 구조는 실제 연산·오차 분석에 사용하라. 새 추상화의 연결이 열려 있으면 작은 구성·예제로 정보를 얻어라.
**산출물:** 구현 가능한 알고리즘, 선택 근거, 검증할 조건.

## C4 실행 DAG·자원

준비·구현·검증의 의존성을 정리하고 독립 작업을 현재 제공되는 실행자에 분담하라. 현재 환경에서 승인 범위의 코드·작은 테스트·기호 계산을 완성하라.
비용은 입력 크기·알고리즘·작업량·측정으로 판단하라. 비싼 실행에는 정확한 코드·명령·입력·반환 계약을 준비하라. 프로젝트별 누적 예산·중단·재개 조건을 보존하라.
**산출물:** 실행 순서, 자원 근거, 필요한 외부 실행 인계.

## C5 구현

실제 입력에서 검증 가능한 출력까지 요청된 기능을 완성하라. 남은 기능은 구체적으로 식별하고 요청 범위의 구현을 계속하라.
변수·단위·컨벤션을 코드에 추적 가능하게 반영하라. 실제 데이터·합성 입력·toy·surrogate의 출처와 용도를 기록하라. 관련 오류 처리와 edge case를 구현하라.
**산출물:** 완결된 변경과 식·입력·출력 대응.

## C6 구현 검증

실제 명령으로 변경에 필요한 계약·오류 처리·회귀·직렬화·경계 사례를 검증하라. 기대값에는 독립 계산이나 명료한 계약을 사용하라.
실패 로그·입력·버전·측정값을 보존하고 원인에 맞게 수정하라. 진단·코드가 바뀌는 생산적인 재실행을 이어가라. 동일 상태 반복은 다음 정보가 되는 검사로 바꾸라.
**산출물:** 실행·출력·종료 상태와 해결된 구현 의무.

## C7 과학 검증

코드가 의도한 방정식·closure·초기/경계조건을 계산하는지 확인하라. 관련 차원·부호·보존량·대칭·물리적 극한·기준 사례를 점검하라.
과학적 오류의 식·원인을 특정해 교정하고 영향받는 결과를 재평가하라. 실행 실패는 해당 입력·알고리즘의 근거로 기록하고 명제의 양화에 맞게 해석하라.
**산출물:** 이론–구현 대응의 근거와 실제 오류의 처리.

## C8 수치·재현성

주장 범위에 맞는 오차·해상도·구간·정밀도·conditioning 의존성, 수렴·안정성을 검사하라. 성능 비교는 같은 입력·정확도·환경 조건과 자원 측정을 연결하라.
build·dependency·입력·seed(관련 시)·명령·출력을 기록하라. 실패·미실행 항목을 원인과 다음 실행으로 연결하라. 추가 시험은 현재 남은 위험을 해소하는 데 맞추어라.
**산출물:** 주장 범위에 맞는 수치·비용·재현 근거.

## C9 독립 검토

중요한 diff, 알고리즘·오차 주장, 기준식·검증의 독립성을 점검하라. 별도 검토자에게 원자료와 과제를 제공하라. 독립 유도·도구 등을 사용하면 실제 방법을 기록하라.
finding은 대상·근거·영향·수정으로 쓰고 관련 검증으로 닫아라. 추가 검토는 구체적인 잔여 위험을 해소할 때 수행하라.
**산출물:** 중요한 지적의 처리와 실제 수용 기준 검토.

## C10 판정·인계

구현 결과, 과학·수치 검증, 실행 여부를 각각 기록하라. 근거를 갖춘 범위로 결과를 진술하고 요청된 변경·보존을 완료하라.
코드·입력·설정·명령·수용 기준·결과·체크포인트·남은 의무를 인계하라. 정책·baseline 교정 이력을 연결하라. 저장은 실제 provider/commit 근거로 보고하고 과학 검증 상태를 별도로 관리하라.
**산출물:** 재실행 가능한 패키지 또는 프로젝트 변경, 결과와 재개점. 계속 수행이 요청된 승인 단위는 이어가라.

## 이론과 주고받기

이론에서 정의·유도·근사·계산식·조건·근거·남은 의무를 받아라. 계산의 반례·불안정성·오차 기작은 원래 명제·입력에 연결해 필요한 이론 단계로 돌려보내라. 이미 확보한 다른 근거는 유지하라. 상태·외부 실행 계약은 `EVIDENCE_AND_HANDOFF.md`를 적용하라.
