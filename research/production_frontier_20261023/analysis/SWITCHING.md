# 상황별 전환 연구: 동일 체크포인트에서의 유한 비용 탐색

## 질문과 기존 근거

범용 솔버는 많은 스텝을 요구하는 문제를 모두 강성 문제로 취급해서는 안 된다. 이전 패키지의 864회 실험에서 빠른 회전의 제공 JVP 전환 경로는 같은 표본 오차 기준에서 유지형 DOPRI5보다 약 32.5배 느렸다. 이는 기존 자료 `research/adaptive_causal_20261023/analysis/SWITCHING_BENCHMARK_KO.md`와 그 원시 결과를 재사용한 관찰이다. 이번에 그 수치를 새로 측정한 것처럼 취급하지 않는다.

현재 기본 `DerivativeFallback::Forbidden` 경로는 이미 단일 DOPRI5 세션을 사용한다. 반면 사용자가 derivative 경로를 허용한 경우의 스텝 압력 휴리스틱은 RODAS가 실제로 유리한지 확인하지 않고 전환하며, 각 배치에서 워크스페이스와 제어기를 다시 만든다. 이 두 문제를 분리했다.

## 후보의 분기와 선택

| 후보 | 한 가지 변경 | 장점 | 남은 위험과 판정 |
|---|---|---|---|
| SW-A | 기존 압력 기반 진입 유지 | 이미 게시된 결과와 호환 | 빠른 진동에 대한 불리한 전환 반례가 있어 권장 정책으로 채택하지 않음; 비교 기준으로 유지 |
| SW-B | 양쪽 드라이버를 체크포인트 가능한 지속 세션으로 변경 | FSAL·제어기·행렬 캐시 재사용 가능 | 네이티브 드라이버 모두의 부분 실패·provider 변경·재시작 계약을 바꾸어야 함; 이번 파일 범위에서 안전성을 입증하지 못해 후속 구현으로 보류 |
| SW-C | 동일 체크포인트의 유한 implicit 재생 실험으로 진입을 심사 | 진동을 강성으로 이름 붙이지 않고 실제 드라이버의 완료·작업량을 확인 | 국소 허용오차와 작업량 지표만 비교하며 시간·전역 오차의 동등성을 보장하지 않음; 명시적 실험 옵션으로 구현 |

이는 세 후보에 대한 유한한 다목적 탐색이다. 확률적 UCT 수렴이나 전역 최적성을 주장하는 MCTS 결과가 아니다. 정확성 제약을 통과한 후보의 비용·적용 범위·구현 위험을 분리해 판단했다.

## 구현과 수학적 계약

`SwitchingConfig.implicit_pilot_attempt_budget > 0`으로 SW-C를 활성화한다. `implicit_pilot_limit`은 전체 실행의 진입 실험 수를, `entry_cost_ratio`는 허용 작업량 비율을 정한다. 기본값은 각각 0, 1, 0.8이다. 0인 기본값은 기존 명시적 전환 정책과의 호환을 유지한다. `Forbidden`은 이 옵션과 관계없이 단일 RHS-only 경로를 유지한다.

명시적 배치가 체크포인트 $(t_a,y_a)$에서 시작하여 내부적으로 수락된 $(t_b,y_b)$까지 진행하면, 실험은 **동일한 $(t_a,y_a)$에서 동일한 $t_b$까지** 허용된 RODAS로 계산한다. 원래 명시적 후보의 내부 수락 상태를 유지하며 재생 실험의 상태는 사용하지 않는다. 실험이 목표에 도달하고

$$W_I\leq\rho W_E,\qquad 0<\rho<1$$

이면 이후 구간에서 implicit 경로로 전환한다. $W$는 기존 `RHS + JVP + df/dt + n·Jacobian + linear solves` 지표이다. FLOP나 벽시계 시간이 아니다. 명시적 배치의 거절된 시도가 $t_b$ 너머를 평가했을 수 있어 두 작업 집계의 실제 평가 시간 영역까지 완전히 일치하는 것은 아니다. 이 때문에 비교는 성능 휴리스틱으로 남는다.

실험이 미완료·고비용이면 명시적 수락 상태에서 계속한다. 실험 수를 소진했다고 implicit을 허용하지 않는다. fatal callback이면 다른 방법으로 재시도하지 않고 이미 수락된 명시적 상태를 보존한 채 중단한다. 결과의 `segments`는 disposition 순서이다. 재생 실험 항목이 자신이 평가한 명시적 후보 앞에 기록되지만, 실제 실행은 명시적 후보가 먼저다.

### 정리 1: 탐색 시도 수의 상한과 상태 보존

각 진입 실험 시도 상한을 $P$, 실험 수 상한을 $L$, 전체 시도 예산을 $B$라 하자. 네이티브 드라이버가 지정된 시도 예산을 준수하면 진입 실험에 소비되는 시도 수는

$$N_{\rm pilot}\leq\min(LP,B)$$

이며, 모든 기존 배치와 버려진 실험의 총 시도는 $B$ 이하이다. 실험은 게시되는 물리 상태를 변경하지 않는다.

**증명.** 각 호출 직전에 잔여 예산 $B-N$을 계산하고 실험 상한을 $\min(P,B-N)$으로 설정한다. 호출 직후 반환된 모든 시도를 $N$에 더한다. 따라서 귀납적으로 $N\leq B$이다. 카운터를 증가시켜 실행하는 진입 실험은 최대 $L$개이며 각각 $P$ 이하이므로 별도 합은 $LP$ 이하이다. 실험의 상태는 `commit`에 전달되지 않고, 명시적 드라이버의 수락된 후보만 전달된다. 따라서 실험 성공·실패가 후보를 덮어쓰지 않는다. □

이는 **시도 수**의 상한이다. 한 시도 안의 RHS·선형 반복 수나 user callback의 실행 시간을 상수로 가정하지 않으므로 시간 상한으로 바꾸어 말할 수 없다.

### 정리 2: 안정된 비용 구조에서의 손익분기

동일 길이 구간들의 정확도 계약이 모두 충족되고 명시적 비용이 구간마다 $E>0$, implicit 비용이 $I\leq\rho E$라고 가정하자. 최초 명시적 구간을 물리적으로 진행하고 이를 implicit으로 재생한 뒤 $K$개 구간을 implicit으로 진행하면 총비용은 $E+(K+1)I$이다. 전 구간을 명시적으로 계산하는 비용 $(K+1)E$보다 작으려면

$$K>\frac{I/E}{1-I/E}$$

이면 충분하다. 특히 $\rho=0.8$이면 이후 다섯 구간부터 엄밀한 작업량 감소가 보장된다.

**증명.** 두 비용 차이는 $(K+1)I-KE$이다. $r=I/E<1$로 나누고 정리하면 $(K+1)r-K<0\iff K>r/(1-r)$이다. □

이는 구간별 비용과 정확도 조건이 유지되는 경우의 구성적 상한이다. 상태 의존성·회전수·이벤트·전환 과도상태로 비용이 바뀌는 일반 ODE에는 적용 가정을 별도로 검증해야 한다. 이 구현은 미래 비용을 관측하지 않으므로 온라인 무후회 보장을 제공하지 않는다.

### 전역 오차의 한계

두 방법의 embedded 국소 오차 검사를 모두 유지하지만, 같은 `rtol`은 같은 전역 오차가 아니다. 흐름이 Lipschitz 증폭 $e^{Lh}$를 만족하고 진짜 국소 결함이 $\eta_k$ 이하라는 별도 증거가 있으면 반복 삼각부등식으로

$$\|e_N\|\leq e^{LT}\|e_0\|+\sum_k e^{L(T-t_{k+1})}\eta_k$$

를 얻는다. 현재의 embedded 추정량을 무조건 $\eta_k$의 보증 상한으로 치환하지 않는다. 따라서 새 비교 예제는 공통 출력 시각의 실제 해석해 오차, 빠른 회전의 위상·진폭 오차를 함께 기록한다.

## 실행·검증 절차

구현: `crates/vigilode/src/switching.rs`.

새 계약 시험: `crates/vigilode/tests/frontier_switch_contracts.rs`. 빠른 JVP 회전의 고비용 진입 거절, 같은 수락 prefix 비교, fatal callback 한 번만 진입, 실험과 전체 예산 합산, 사전 설정 검증, derivative 금지 경로 보존을 검사한다. 기존 `switching_contracts`도 수정된 제어 흐름의 회귀 대상으로 함께 실행한다.

새 비교 예제: `crates/vigilode/examples/frontier_switch_bench.rs`. `decay`, `rapid`, `prothero`, `transition`과 `rhs`, `legacy-fd`, `legacy-jvp`, `screen-fd`, `screen-jvp`를 지원한다. `--rtol`, `--source-commit`을 명시할 수 있고, 각 실행은 전체 수락 상태·버려진 실험·원래 드라이버 작업 기록을 JSON 한 줄로 출력한다. 빌드와 직렬화를 제외한 호출 비용을 기록하되, 같은 기계에서 소스 고정 후 단독 측정한 캠페인만 성능 판단에 사용해야 한다.

```
cargo test -p vigilode --locked --offline --test switching_contracts --test frontier_switch_contracts
cargo build -p vigilode --locked --offline --profile measurement --example frontier_switch_bench
frontier_switch_bench --case rapid --mode screen-jvp --rtol 1e-7 --source-commit <fixed-source>
```

## 고정 소스 실험 결과와 반례

최종 네이티브 시험 중 이 변경과 직접 관련된 새 계약 6개와 기존 전환 계약 14개가 모두 통과했다. 영수증은 `evidence/native_facade_tests_final.log`에 있다. 전체 frontier 네이티브 시험 59개 통과와 구분하여, 이 절의 전환기 시험 수는 **20개**로 센다. 개발 중 실패한 빌드·assertion 기록은 삭제하지 않았다.

고정 소스 `55ad7ec6af8b127cb90849db56abff4f02b9920b`에서 CPU0 단일 스레드로 4문제 × 5방법 × 2허용오차 × 3회 = **120개 측정 행**을 얻었다. 각 설정의 별도 워밍업 한 번은 시간 중앙값에 포함하지 않았다. 114회가 완료했고, 나머지 6회는 RHS-only Prothero의 25,000회 시도 예산 소진이었다. 이는 캠페인 자체의 시간 초과가 아니다. 모든 실패와 부분 상태는 원시 JSON에 보존했다.

아래 비교는 사전에 정한 `rtol=10⁻⁶,10⁻⁸` 중 공통 표본 시각에서의 절대 오차 상한 **10⁻⁵**를 모든 반복에서 충족한 가장 빠른 설정을 방법별로 선택했다. 실제 오차 자체가 서로 같다는 뜻은 아니며, 연속 시간 전체의 전역 정확도를 보증하지도 않는다. 비용은 문제·옵션·워크스페이스 구성과 모든 버려진 실험을 포함한 실행 시간의 3회 중앙값이다. 출처는 `results/switching_campaign/PLAN.json`, `SUMMARY.json`, `ROWS.json`, `RECEIPTS.json`과 개별 원시 기록이다.

시간비가 1보다 크면 이 오차 예산 안에서 심사 방법의 중앙값이 더 짧다. **빠른 회전의 제공 JVP에서는 개선을 실제로 관측했다.** 기존 진입은 JVP 106,717회였으나 심사 방법은 한 번의 실험에 512회만 사용하고 implicit 진입을 거절했다. 반면 빠른 회전의 FD에서는 실제 오차가 더 작아졌지만 같은 오차 예산을 충족하는 선택지 간 중앙값은 약 2.03배 느렸다. 따라서 이 결과를 FD 방법 전체가 정확도–비용 면에서 지배된다는 말로 확대하지 않는다.

가장 명확한 새 반례는 **강성 전이**이다. 심사 방법은 초기 실험 한 번을 거절한 뒤 실험 수 제한을 소진하여 전환하지 않았다. 이 실행에서 기존 FD 경로는 두 번 전환하고 더 작은 오차로 끝냈지만, 심사 FD는 RHS 8,403회와 시도 1,384회를 소비하여 약 3.05배 느렸다. 한 번의 초기 관측을 전체 궤적에 일반화하는 정책이 실패한 사례다. 이 반례는 향후 epoch 또는 비용 변화 기반 재탐색의 필수 회귀 사례로 남긴다.

작은 감쇠계에서도 허용된 전환 경로가 지속 RHS 경로보다 약 1.88배 느려, 워크스페이스·제어기의 배치별 재시작 비용이 여전히 문제로 남았다. 빠른 회전에서 심사 JVP의 4.158ms와 유지형 RHS의 4.479ms 차이는 반복 범위가 겹치고 표본 수가 작으므로 안정된 RHS 대비 속도 향상으로 주장하지 않는다. 빠른 회전의 기준 JVP 범위는 39.280–158.670ms, 심사 JVP는 4.013–11.919ms였다. 모든 중앙값은 이 제한된 환경의 관측치이다.

따라서 SW-C는 빠른 회전에서 비싼 제공 JVP 진입을 막는 **문제 특화 실험 경로**로 유지하지만, 범용 기본 정책 후보로는 이번 범위에서 제외한다. 지속 세션을 먼저 구현하고, 그 위에서 모델 epoch 또는 수락 비용 추세 변화에 반응하는 유한 재탐색을 추가하는 순서가 필요하다. 아직 구현되지 않은 이 변경의 속도 향상 수치를 추정하지 않는다.

| C5–C6 | 새 계약 시험과 기존 전환 회귀 시험, 실제 오차 기록 예제 구현 |
| C7–C8 | 독립 검토의 `is_probe` 의미와 disposition 순서 지적을 반영; 불필요한 상태 복사를 실험 가능 기간으로 제한 |
| C9–C10 | 최종 전환 계약 20개 통과 및 단일 스레드 120행 캠페인 완료; 실패·실제 오차·원시 작업 기록 보존 |

## 남은 개발 단계

1. **지속 세션:** DOPRI5와 RODAS의 `advance_to`/accepted checkpoint API를 분리한다. 저장 대상은 상태·시간·다음 h·FSAL·제어기·provider epoch이며, RODAS 캐시는 h/provider/격자 변경 조건에 따라 무효화한다. 바뀌지 않은 단일 방법의 출력·카운터 일치, 복구 가능 오류, fatal 오류, 부분 상태를 검증한 뒤 전환기에 연결한다.
2. **실험 기간과 시점:** 한 번의 작은 초기 prefix에서 implicit이 비경제적이었다는 사실은 나중의 강성 전이를 배제하지 않는다. 모델 epoch 또는 수락된 비용 추세 변화에 따라 제한된 재실험 예산을 배분하되, 총 비용 cap을 유지해야 한다.
3. **시간 지표:** 실제 callback 비용과 하드웨어가 다른 이상 현재의 합성 지표는 시간 순위를 보장하지 않는다. 반복 가능한 카운터 정책과 선택적 시간 측정 정책을 별도로 제공하고, 모든 실험 비용까지 포함한 달성 오차–시간 전선을 비교한다.
4. **fatal 즉시 종료:** 기존 `fd.rs::Guard::call`은 fatal과 recoverable 오류를 모두 `CoreError::NonFinite`로 전달한다. 사용자 callback 재진입은 막지만 네이티브 드라이버가 남은 시도를 short-circuit로 소비할 수 있다. 새 pilot 시험에서 Jacobian 사용자 호출 한 번과 시도 빌드 12회가 관찰되었다. recoverable/fatal의 네이티브 구분과 부분 결과 반환 계약을 함께 확장해야 하며, 오류 타입만 임의로 바꾸면 작업 기록과 수락 상태가 유실될 수 있다.

판정: **전환 계약 검증은 통과했으나 범용 production 기본 정책 승격은 HOLD이다.** 빠른 회전의 제공 JVP 경로에는 관측된 이득이 있고, FD·강성 전이에는 보존해야 할 손실 반례가 있다. 기본 RHS-only 계약은 유지하며, 지속 세션과 변화 감지에 따른 유한 재탐색을 구현한 뒤 같은 원시 사례와 실제 오차 예산으로 재평가한다.
