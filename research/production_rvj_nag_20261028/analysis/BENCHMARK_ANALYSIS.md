# 등록된 RVJ 실험: 전체 반복을 보존한 성능·인증 분석

**결론:** 고정 cyclic-closure 모델에서는 원래 물리 오차 상한을 유지하면서 native 인증 비용을 줄였다. 같은 N=64에서 전체 시간 중앙값은 direct 경로가 빠르고, 등록된 격자 중 처음 인증되는 지점도 historical N=64에서 direct N=32로 줄었다. Trace 공유 회로는 field 및 point-enclosure 단계에서 빨랐지만, 전체 candidate trajectory 중앙값은 오히려 느렸다. Trace 전체 인증 workflow의 속도 개선은 주장할 수 없다. **Production 상태는 HOLD이다.**

## 1. 출처와 집계 규칙

실행 소스는 `64004e23042f2cf076da5378be724f50c3856f4c`이다. Run receipt의 remote SHA와 일치하며 `closure.json`, `trace.json`, `ORACLE_RESULTS.json`의 SHA-256도 receipt와 일치함을 확인했다. 등록된 실행은 `PASS`, 독립 원래 방정식 oracle은 `PASS_SCOPED_ALL_EXPORTED_SLABS_CHECKED`이며 732,947개의 검사를 기록했다. 이 문서 작성에서는 **기존 JSON을 읽고 집계했을 뿐**, native/CAS/solver/oracle를 다시 실행하지 않았다.

모든 timing cell의 측정 7회를 유지했다. 최솟값을 대표값으로 택하거나 느린 반복을 제거하지 않았다. 사전 지정 warmup 1회는 원래 프로토콜대로 측정 반복과 구분된다. 표의 대표값은 7회 중앙값이며 `[최솟값, 최댓값]`을 함께 제시한다. 비율은 `baseline 중앙값 / candidate 중앙값`으로 1보다 클 때 candidate가 빠르다. 반복별 짝 비율과 범위 겹침도 JSON에 보존했다. 이들은 신뢰구간이나 일반적 성능 보장이 아니다.

인증 비용 비중은 각 반복에서 `(endpoint preparation + certificate) / total`을 계산한 뒤 집계했다. 별도로 계산한 component 중앙값을 더하면 total 중앙값과 일치할 필요가 없다. `total - candidate - preparation - certificate`의 나머지도 JSON에 남겼다. Accuracy admission은 원자료의 정확한 판정을 유지하며 표시용 float 반올림으로 다시 판정하지 않는다.

환경: `Linux-6.18.55-x86_64-with-glibc2.39`, Rust `measurement` profile, `RAYON_NUM_THREADS=1`, `OMP_NUM_THREADS=1`. 실행 후 보조 관측인 `../evidence/ENVIRONMENT.json`은 CPU `AMD EPYC 9V74 80-Core Processor`, 허용 affinity `0–8`(9개 CPU), 명시적인 taskset 고정 없음, native run concurrency 1을 기록한다. 보조 관측 시각은 `2026-10-28T10:40:13.935741+00:00`이다. 주파수와 hardware performance counter 자료는 없으며 공유 container에서 측정한 phase wall time과 소스 작업량이다. 결과는 이 환경의 일곱 반복에 한정한다.

## 2. Cyclic closure: 정확도 기준을 통과하는 격자

물리 norm은 전체 상태 infinity norm, cap은 정확히 `1/100000000`이다. `n`은 closure 크기이며 내보낸 lifted state의 성분 수는 `2n`이다. 아래 시간은 candidate, endpoint preparation, native certificate와 범위 안의 할당 비용을 포함한다. 동일 격자에서 세 arm은 동일한 candidate endpoint bits를 사용한다.

## 3. Trace: field 절감과 trajectory 결과를 분리

각 field timing block은 동일한 N=128 direct 궤적의 129개 상태를 16회 평가한다. 따라서 block당 2,064개 입력이다. Trajectory block은 N=128 궤적 16개이며 동일한 direct-moment forcing을 포함한다. Point interval enclosure 비용과 whole-path 인증 비용은 다르다.

| Phase | Direct μs: 중앙값 [min,max] | Shared μs: 중앙값 [min,max] | Direct/shared | shared가 빠른 반복 | 범위 겹침 |
|---|---:|---:|---:|---:|---|
| candidate_field | 75.404 [74.502, 165.469] | 63.145 [62.644, 71.337] | 1.1941 | 7/7 | 아니오 |
| interval_field | 1143.962 [1050.851, 1411.494] | 763.960 [677.179, 1039.664] | 1.4974 | 7/7 | 아니오 |
| combined_field | 1184.933 [1044.512, 1378.796] | 926.304 [831.912, 1012.564] | 1.2792 | 7/7 | 아니오 |
| candidate_trajectory | 607.695 [596.027, 689.698] | 667.394 [577.499, 722.538] | 0.9105 | 4/7 | 예 |

공유 field 회로의 산술 절감은 실제 계수에도 나타난다: field당 direct 13 multiplications/9 additions, shared 8 multiplications/7 additions다. 후보 field, interval field, combined field 중앙값은 감소했다. 그러나 candidate trajectory는 direct 607.695 μs, shared 667.394 μs로 shared가 약 9.824% 느렸다. 원자료 범위가 크게 겹치고, 원래 forcing 및 RK4/할당 비용을 포함하므로 이 실험으로 trajectory의 안정적인 성능 차이나 개선을 주장하지 않는다. 느린 반복을 제거하거나 해당 결과를 field-only 수치로 대체하지 않았다. 같은 repeat끼리 나눈 비율의 중앙값은 1.00837이며 shared가 빠른 repeat가 4/7회다. 이는 서로 독립적으로 구한 두 시간 중앙값의 비율 0.91055와 다른 통계다. 두 수치를 모두 유지하며 안정적인 개선이나 보편적인 regression을 확정하지 않는다.

### Whole-path oracle gate와 manufactured-reference 대조

아래 숫자는 두 route에서 동일한 결과다. 공식 `physical_budget_met`는 원래 방정식 residual 기반 whole-path 상계를 사용한다. 정확한 quintic reference와의 전 구간 비교는 별도 diagnostic이며 이 gate를 소급 변경하지 않는다.

| 16 | 5.03622e-07 | 2.48785e-05 | 미통과 | 1.80247e-06 |

N=64의 node error가 cap 아래라는 사실만으로 residual 인증을 통과시킬 수 없다. 더 강하게, 이 manufactured problem에서는 별도 정확한 전 구간 reference 비교도 N=64부터 cap 아래임을 보인다. 따라서 N=64·128의 residual-gate 미통과는 실제 물리 오차 위반이 아니라 현재 일반 residual 상계의 보수성이다. 공식 residual-based gate의 첫 통과는 양쪽 route 모두 N=256이며 상계는 5.31652523010e-9이다. 이번 exact oracle은 정확한 `lambda=39/64`와 기존의 유효한 보수적 전파식 `E/(1+lambda*h)+h*delta`, whole-slab 식 `E+h*delta`를 사용했다. TRACE.md의 더 날카로운 두 rational exponential bound 전파식까지 실행한 결과로 해석하면 안 된다.

직접 집계한 두 route의 state/time bit 비교는 JSON에 포함했다. 이 bounded grid에서는 서로 다른 field 회로가 내보낸 상태 비트가 동일하다. 선택된 실수 가지와 real-only query 거부, triple-root의 distinct-count 변조 거부도 기존 oracle 결과에 보존되어 있다.

## 4. 외부 정확 인증 비용과 주장 한계

| 구간 | 기록된 시간, s | 의미 |
|---|---:|---|
| Closure exact oracle | 10.775910623 | 모든 closure cell의 독립 검증 합계 |
| Trace exact oracle | 2.564409354 | 10개 trajectory, 992개 slab 등의 독립 검증 합계 |
| Oracle 내부 총시간 | 13.362724506 | 입력 처리 등 공통 작업을 포함한 내부 계측 |
| Oracle process wall | 13.466613229 | receipt의 전체 프로세스 시간 |

Trace oracle에는 route별·grid별 독립 timing이 없다. 이 합계 시간을 임의로 나누어 candidate timing에 더하거나, native point-enclosure timing을 whole-path 인증 timing으로 대체해서는 안 된다. 따라서 전체 인증 workflow의 route speedup은 계산하지 않았다. Native root-enumeration baseline도 없으므로 root enumeration 대비 speedup도 주장하지 않는다.

Closure native certificate는 whole-path residual/tube bound 자체를 출력하므로 그 native 인증 비용은 위 closure whole-call 비교에 포함된다. 외부 oracle은 그것을 독립 검증하는 추가 비용이다. Trace에서는 이번 whole-path 인증이 외부 exact-rational 경로에 있으므로 두 경우의 인증 위치를 같은 것으로 취급하지 않는다.

## 6. 다음 개발 판단

이번 evidence는 고정 모델의 인증 산술 및 명시적인 all-root observable provider에 대한 scoped 결과다. Adapter/switcher의 별도 비용이나 기본 production dispatcher를 측정한 데이터가 아니므로 그 병목이 해결됐다고 해석하지 않는다. 실제 모델 provider, 일반 multivariate quotient/branch semantics, 누적 production gates 및 사용 환경 검증은 계속 남는다.

후속 작업의 근거는 다음과 같다. Closure는 정확한 원래 방정식 certificate를 유지하면서 endpoint preparation과 certificate가 차지하는 비용을 더 줄이는 것이 타당하다. Trace는 field-only 절감을 전체 trajectory 개선으로 연결하려면 실제 driver 비용의 분리 계측이 먼저 필요하다. Residual 인증 상계와 실제 reference path bound의 차이는 더 날카로운 continuous certificate에 대한 이론 연구 과제이며 경험적 safety multiplier를 줄여 해결할 대상이 아니다.

현재 방식은 각 slab의 잔차 supremum을 부호 없는 forcing으로 전파하므로 잔차의 signed cancellation을 잃을 수 있다. 이것은 수학적으로 가능한 메커니즘이며 이번 timing/error 관측에서 원인으로 분리·확정된 결과는 아니다. 후속 DAG에는 원래 residual

\[
R(t)=\widehat y'(t)-F(t,\widehat y(t)),\qquad
\rho(t)=\int_{t_i}^{t}R(s)\,ds,\qquad z=\widehat y-\rho
\]

를 이용하는 local certificate 연구를 제안한다. 그러면 정확히

\[
z'-F(t,z)=F(t,\widehat y)-F(t,z)
\]

이다. `D=[1/2,1]^2`에서 이미 확보한 `lambda=39/64`와 원래 벡터장의 absolute infinity-Lipschitz 상계 `L=75/64`를 사용하면, corrected path 및 필요한 tube가 D 안에 있다는 조건 아래

\[
\|y(t)-\widehat y(t)\|_\infty\le
\|\rho(t)\|_\infty+e^{-\lambda(t-t_i)}E_i+
L\int_{t_i}^{t}e^{-\lambda(t-s)}\|\rho(s)\|_\infty\,ds
\]

형태로 원래 physical error로 되돌리는 연구가 가능하다. Absolute row-sum 상계는 각각 `445/512`, `75/64`이므로 후자가 전체 `L`이다. `rho`의 표현·산술 오차, corrected-path 도메인, first-exit 조건과 전체 인증 비용을 함께 증명·검증해야 한다. 이 제안에 대한 새 코드나 실험은 이번 분석에서 수행하지 않았다.

원본 반복과 실패 cap cell을 유지한 채 이 결과를 handoff해야 한다. 본 분석은 새로운 수정 루프나 추가 측정의 근거를 만들어내지 않으며, source code와 등록된 실행은 변경하지 않았다. **Production HOLD를 유지한다.**
