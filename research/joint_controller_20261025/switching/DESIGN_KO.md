# 적응 정보와 방법 재탐색의 결합

이번 변경은 `SwitchingConfig::adaptive_evidence(...)`와 `AutomaticOde::solve_adaptive(...)`로 선택한다. 기존 `evidence_driven(...)`, `AutomaticOde::solve(...)`, 도함수 금지 기본 경로는 유지한다.

## 확인한 병목과 구현

출발 소스는 `4fe67602502440d76aa9dd245c6b1d67558c14bf`의 tree `8bab954cffcf7abd9cdd0ca528567ece47e43bc7`이다. 해당 브랜치에서 연속 명시법 구간의 PI, FSAL, workspace 유지가 이미 구현되었다. `external_reports/adapter_local_followup_20261025/REPORT_KO.md`는 회전 문제에서 버린 RODAS 진입 비교 여섯 번과 1,150 RHS를 보고했다. 따라서 이번 수정 대상은 이미 해결된 세션 재생성이 아니라, 비슷한 상태에서 반복하는 비교 비용이다.

하나의 명시법 batch에서 얻은 작업량 $w$, 실제 전진 시간 $\Delta t$, 다음 스텝 제안 $h^+$, 거절 비율 $r$를 함께 사용한다. RODAS 비교가 불리하면 이 네 관측값을 저장하고 다음 비교까지의 batch 간격을

\[
d_k=\min(M,b2^k),\qquad b=4,\quad M=64,
\]

로 늘린다. $k$는 연속된 불리한 비교 횟수다. 초기 비교 직후 간격은 여덟 batch다. 다음 중 하나가 발생하면 오래된 판단을 재사용하지 않고 실제 경쟁 비교를 다시 수행한다. 작업률이 좋아지는 방향도 비교의 유효범위를 벗어날 수 있으므로 양방향 변화를 다룬다.

1. 적어도 네 수락 스텝을 포함한 batch에서 $w/\Delta t$가 저장값의 두 배 이상이고 $h^+$가 저장값의 절반 이하가 된다.
2. 적어도 네 수락 스텝을 포함한 batch에서 $w/\Delta t$가 저장값의 절반 이하이고 $h^+$가 저장값의 두 배 이상이 된다. 이 완화 신호는 다음 자격 있는 batch의 비교를 예약한다. 해당 비교는 이후 자격 있는 prefix의 수락 checkpoint에서 시작한다.
3. 적어도 두 거절이 발생하고 거절 비율이 저장값보다 0.2 이상 높아진다.
4. 재시도 간격이 만료된다. 최대 64 batch가 지나면 재확인 자격을 되돌린다. 실제 비교는 최종 시각 이전의 다음 work-pressure batch에서 수행된다.

앞의 세 변화 신호는 재탐색만 요청한다. 완화 신호의 예약은 실제 비교가 이루어질 때까지 유지하고, 비교 자격이 없었던 중간 batch에서 소모하지 않는다. 실제 RODAS 진입은 동일한 물리 상태와 같은 수락 prefix에서 RODAS를 실행하고, 완주와 기존 0.8 작업량 비율을 확인한 뒤 결정한다. 작은 스텝 자체에 강성이라는 이름을 붙이지 않는다. 새 방식에서 과거의 전체 실행 pilot 횟수 제한은 사용하지 않는다. 모든 명시법, 암시법, 버린 비교의 시도는 기존 단일 `Options::max_steps` 한도에 합산되므로 실행 자원 상한은 계속 적용된다. pilot에 전체 비용의 일정 비율만 쓰게 하는 credit 예산은 별도 후속 기능이다.

명시법으로 복귀하면 관측 기억을 초기화한다. 모델·도함수 제공자·좌표·허용오차가 고정된 하나의 `solve` 내부에서만 기억을 사용하고, 다른 실행으로 내보내지 않는다. 암시법 진전 후에는 기존 구현대로 명시법 FSAL과 제어기를 폐기한다. 불리한 비교를 줄여도 명시법의 물리 궤적이나 허용오차를 변경하지 않는다.

반대 방향인 RODAS→DOPRI 복귀도 결합했다. 이전 implicit window의 비용률은 추가 검사의 저렴한 신호로 사용한다. 이 신호가 유리하고 명시법 복귀 probe가 끝까지 도착하면, **동일 checkpoint에서 동일 window 끝까지** RODAS를 한 번 실행해 실제 비용을 비교한다. DOPRI가 유리하면 이미 얻은 명시해를 수락한다. RODAS가 유리하고 끝까지 도착했다면 그 비교해를 곧바로 수락하여 같은 암시 구간을 다시 계산하지 않는다. RODAS 비교가 불완전하면 이를 복귀 근거로 쓰지 않는다. 비교 중 fatal callback은 직전 수락 checkpoint에서 중단하며, 버린 명시 probe의 끝점을 성공으로 게시하지 않는다. 남은 전체 예산이 0 또는 1인 경우도 계약 시험에 포함했다.

## 실제 첫 pilot에서 발견한 교정

첫 실제 pilot에서 case5의 새 정책은 2,463 RHS를 사용해 기존 정책의 1,887 RHS보다 비쌌다. 첫 비교는 $t=0$에서 $6.469\times10^{-6}$까지의 초기 과도구간에 해당했다. 명시법 작업량 193에 대해 RODAS 작업량은 406이었다. 다음 명시 batch에서는 제안 스텝이 $5.1068\times10^{-7}$에서 $3.511\times10^{-6}$으로 증가하고 물리 시간당 작업률은 약 $2.98\times10^7$에서 $2.55\times10^6$으로 감소했다. 악화만 검사하던 초기 정책은 이 변화를 무시하고 여덟 batch를 기다렸다.

이 문제에는 정확한 구조 $z=x-\cos y$, $z'=-z/\epsilon$이 있다. 빠른 과도성분이 줄면서 초기 정확도 제한이 풀려도 명시법의 안정성 제한은 남는다. 두 방법의 비용이 같은 비율로 개선된다는 전제가 없으므로, 명시법이 빨라졌다는 사실만으로 초기의 불리한 RODAS 비교를 계속 재사용할 수 없다. 교정은 기존 두 배/절반 임계값을 반대 방향에도 대칭적으로 적용하고 `WorkRegimeRelaxed` 이유를 기록하는 것이다. 새 신호도 실제 동일-prefix 비교만 요청한다.

첫 교정은 완화 신호를 발견한 즉시 바로 전 prefix를 다시 계산했다. 실제 비용은 2,763 RHS로 증가했다. 두 번째 RODAS 비교는 $6.469\times10^{-6}$에서 $8.183\times10^{-5}$까지 과도구간 일부를 다시 포함했고, 작업량 250 대 192로 여전히 불리했다. 원인은 새로운 endpoint의 제어기 상태와 방금 종료된 구간의 경제성을 같은 위치의 관측으로 취급한 것이다. 최종 교정은 `PendingRegimeComparison`으로 비교를 다음 자격 있는 명시 prefix까지 예약한다. 이렇게 해야 RODAS 비교도 새로 도달한 상태에서 시작한다. 임계값은 바꾸지 않았다. 첫 원자료와 실패한 교정의 원자료를 각각 보존하고, 이후 시험에는 별도 전이 위치 0.43과 0.87을 사용한다.

## 동일한 비용 비교 경계

`selection_evidence::compare_qualified_costs`를 실제 진입 결정에서 호출한다. 새로 계산한 두 기록에는 같은 checkpoint/prefix 식별자를 부여하고, 단위는 관측된 `Work` 점구간으로 설정한다. 비교 대상은 각 native solver가 동일한 물리 좌표의 요청된 국소 허용오차로 수락한 prefix다. 이에 대응하는 비용 비교는

\[
w_{\rm RODAS}\le 0.8w_{\rm DOPRI}
\]

이며 경계 산술은 보수적으로 처리한다. 복귀 방향도 같은 함수에서 incumbent와 candidate를 바꾸어 검사한다. 시간 초 단위, 전역 오차 인증, 앞으로의 구간에 대한 비용 예측은 이 점구간에 포함하지 않는다. 이 구분을 통해 실행 병렬화의 시간 비교와 방법 선택의 작업량 비교가 같은 함수로 검사되면서도 서로 다른 단위를 섞지 않는다.

## 비교 횟수 감소의 조건부 계산

모든 비교가 불리하고, 양방향 국면 변화나 거절 악화 신호가 없으며, 모든 batch가 비교 자격을 갖는 경우를 고정한다. $N$은 첫 비교가 이루어진 batch를 1로 세는 **전체 명시법 batch 수**다. 아직 최대 간격에 도달하지 않았다면 $p$번째 비교가 가능한 가장 이른 batch 번호는

\[
n_p=1+\sum_{j=1}^{p-1}b2^j
    =1+2b(2^{p-1}-1).
\]

따라서

\[
P(N)\le1+\left\lfloor\log_2\left(1+\frac{N-1}{2b}\right)\right\rfloor.
\]

최대 간격을 포함한 정확한 하한은 $n_p\ge1+\sum_{j=1}^{p-1}\min(M,b2^j)$다. 이 식은 장기 실행에서 주기적 재확인을 남기면서 초기의 반복 비교가 줄어드는 조건을 명시한다. 국면 변화나 거절 악화 신호가 발생하면 새 비교가 가능하므로 이 상한의 전제가 달라진다. 실제 비용은 각 pilot의 기록을 합산한다. batch마다 연산 비용이 다르기 때문에 비교 횟수만으로 초 단위 속도를 결론내리지 않는다.

독립 이론 검토에서 $N$을 pressure batch만으로 세면 안 된다는 점을 교정했다. 코드의 경과 간격은 비교 자격이 없었던 명시법 batch도 포함한다.

## 판별 시험

`adaptive_entry_contracts.rs`는 다음 실제 과제를 검사한다.

- 회전에서 불리한 비교와 총 RHS를 줄이고 최종 물리 상태가 기존 정책과 비트 단위로 일치하는가.
- 알려진 회전해 $y=(\cos100t,\sin100t)$에 대해 완만하게 증가하는 감쇠를 추가한 세 전이 위치 0.35, 0.65, 0.82에서 오래된 비교를 갱신하는가.
- 과거 lifetime pilot 한도를 1로 둬도 새 정책의 sentinel과 악화 감지가 작동하는가.
- 모든 버린 비교를 전체 시도 예산에 합산하는가.
- 도함수 금지와 invalid-input 선행 검사가 유지되는가.
- 실제 동일 window 비교를 통과한 명시 복귀만 수락하는가. 비교 예산 소진과 fatal callback에서 직전 수락 상태 및 모든 비용을 보존하는가.

실제 실행 결과는 부모 통합 검증 기록과 별도 pilot 원자료에 연결한다. `adaptive_entry_pilot`은 선언된 원래 상태의 endpoint 오차 상한, 모든 pilot·전환·workspace 비용을 포함한 solver 시간, 방법 점유 시간, 비교 이유, 각 비교의 성공 여부와 작업량을 출력한다. 시험에 사용한 전이 위치와 분리한 0.47, 0.91의 최초 전이 및 교정 후의 0.43, 0.87 전이, 회전, 초기 강성, case5 및 비강성 대조군을 비교할 수 있다. 비교 횟수와 전체 궤적 비용은 의사결정별 오탐률과 구별한다.

대칭 변화 교정 이전 소스의 `validation/facade_final_r2`에서 facade 전체 232개 시험이 통과했다. 이 변경의 새 계약은 위 아홉 가지 end-to-end 시험과 private routing-state 시험 한 개다. 마지막 시험은 큰 과거 비용률을 명시적으로 주입하고 실제 두 solver를 실행하여, 더 싼 동일-window 암시 비교해가 한 번만 수락되고 거절된 명시 probe와 함께 정확히 계상되는지 검사한다. 이 인공 과거 비용률은 오류 처리용 상태 fixture이며 실제 성능 관측으로 사용하지 않는다. 해당 실행 동안 소스는 변경되지 않았으며 종료 코드는 0이다. 대칭 변화 교정에는 서로 다른 $\epsilon=10^{-3},10^{-6}$의 실제 과도해 시험과 양방향/불일치 변화 신호의 private 계약을 두 개 추가했다. 현재 소스의 실행 결과는 후속 validation 영수증에서 구분한다. 이 계약은 바로 다음 batch가 자격을 갖는 fixture에서 완화 신호의 endpoint와 재비교 시작점이 일치함을 검사한다. 자격 없는 중간 batch가 있는 경우에는 예약을 유지하고, 이후 자격 있는 prefix의 수락 checkpoint에서 비교한다.

예약 비교 교정 이후 `validation/transient_pending_repair`의 17개 library 시험과 10개 integration 시험이 모두 통과했다. 실제 과도해 시험은 원래 요구한 RHS 감소 조건을 유지했고, 새 비교가 신호의 endpoint에서 시작함을 확인했다. 종료 코드 0, 실행 중 소스 불변이다. 벽시계 성능은 별도의 최종 native pilot 결과로 평가한다.

## 최종 제한 검증 결과

최종 `validation/facade_final_r3`에서 facade 시험 234개가 통과했고, 종료 코드 0과 실행 중 소스 불변을 확인했다. 이어 `native_r2/pilot.jsonl`의 9개 사례·162개 실행(27 warmup, 135 timed)이 모두 각 물리 endpoint 오차 상한을 통과했다. 각 정책의 다섯 timed 표본 중앙값을 아래에 적었다. 시간은 workspace·버린 비교·전환을 포함한 solver wrapper 범위다.

case5의 최종 RHS는 1,311로 낮아졌다. 최초의 2,463과 즉시 재비교 교정의 2,763을 거쳐, 신호가 설명하는 endpoint와 실제 비교 prefix를 맞춘 결과다. 다만 이 작은 문제의 측정 중앙값은 약 0.370 ms로 기존과 같아, 작업량 감소와 벽시계 이득을 분리한다. 회전에서는 버린 RODAS 비교가 여섯 번에서 세 번으로 줄고, 명시법 물리 궤적은 기존 정책과 동일하다. 교정 후 새 전이 위치 0.43과 0.87에서도 작업량이 줄었다.

완화 사례의 RHS는 749에서 813으로 증가했다. 추가 64 RHS는 명시법 복귀를 과거 구간의 비용률만으로 결정하지 않고 동일-window에서 확인한 비용이다. 이 비용을 숨기지 않고 비교 예산과 지속 RODAS 세션의 다음 최적화 대상으로 남긴다. 원래부터 방법을 알고 직접 지정한 DOPRI/RODAS는 여러 사례에서 여전히 더 싸다. 전체 궤적 비교와 짧은 시간 측정은 새 policy의 범용 최적성이나 의사결정별 오탐률을 뜻하지 않는다. 전체 원자료와 후보별 동일 오차 상한 검사 결과는 `../evidence/NATIVE_PILOT_SUMMARY_FINAL.json`에 있다.

## 다음 개선

현재 실제 선택 점수는 RHS/JVP/작은 선형해법을 단일 작업량으로 합산한다. 제공자별 초 단위 비용이 크게 다른 경우에는 관측 작업량의 우위가 벽시계 우위로 연결되지 않을 수 있다. 복귀 방향의 과거 비용률 screen도 실제로 더 좋은 명시법을 뒤늦게 시험할 수 있다. 다음 단계는 같은 checkpoint의 자격 있는 비교에 실제 비용 구간을 연결하고, 방법 전환 뒤의 지속 RODAS 세션 비용을 포함하는 것이다. step·오차·좌표 정보가 바뀌었을 때의 유효범위를 명시하여 계산 기하나 causal/homotopy provider가 같은 비교 경계에 들어오도록 한다.
