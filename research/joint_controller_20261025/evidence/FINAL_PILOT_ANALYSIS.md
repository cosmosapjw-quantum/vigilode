# 최종 pilot 분석

최종 switching 실행은 아홉 문제에서 이전 정책, 새 정책, 관련 직접 대안 하나를 비교했다. 각 경로의 warmup 1회와 측정 5회를 합쳐 **162개 실행**이며, 측정 135개 모두 완주·물리 endpoint 오차 상한을 통과했다. `switching/native_r2/RUN.json`은 바이너리 SHA-256, 실행별 명령·종료 코드·출력 해시와 실행 중 소스 불변을 기록한다. 최종 분석 입력과 해시는 `NATIVE_PILOT_SUMMARY_FINAL.json`에 있다. 병렬 실행 및 causal 보정은 변경되지 않은 기존 raw 결과를 재사용했으며 재실행하지 않았다.

## 방법 선택과 재탐색

| 문제 | 이전 → 새 정책 RHS | 새/이전 비용비 중앙값 | 새/직접 대안 비용비 중앙값 | 직접 대안 |
|---|---:|---:|---:|---|
| decay | 79 → 79 | 1.052 | 1.638 | DOPRI |
| rotation | 6,395 → 5,804 | 0.594 | 5.209 | DOPRI |
| stiff-forced | 706 → 706 | 1.035 | 1.000 | RODAS |
| case5 | 1,887 → 1,311 | 1.069 | 2.233 | RODAS |
| relaxation | 749 → 813 | 0.943 | 1.551 | RODAS |
| 전이 중심 .43 | 173,988 → 30,480 | 0.510 | 0.635 | RODAS |
| 전이 중심 .47 | 162,308 → 31,122 | 0.578 | 0.726 | RODAS |
| 전이 중심 .87 | 46,270 → 30,694 | 0.873 | 0.407 | RODAS |
| 전이 중심 .91 | 34,749 → 30,215 | 0.829 | 0.394 | RODAS |

비용비는 같은 repetition에 속한 두 실행의 inclusive solver time을 나눈 뒤 다섯 비의 중앙값을 취한 것이다. 이 값은 두 시간 중앙값의 비와 다르다. 시간은 해당 호스트의 짧은 진단 측정이며, 작업량은 별도로 제시했다. 공통 endpoint 오차 상한은 case5에서 1e-4, 나머지에서 1e-5이고 달성 오차는 경로별로 다르다.

rotation에서는 불필요한 후보 재평가를 줄여 버린 probe RHS가 1,150→559로 감소했다. 이전 정책보다 빨라졌지만 직접 DOPRI에 비해서는 여전히 다섯 반복 모두 느렸다. 전이 중심 .43/.47/.87/.91에서는 이전 정책이 implicit 경로에 진입하지 못했고, 새 정책은 필요한 후기 구간에서 진입했다. 이 네 조건의 새 정책은 직접 RODAS보다도 다섯 반복 모두 빨랐다. 앞쪽 비강성 구간에서 명시법을 유지한 뒤 전환하는 조합의 이득이다. .43과 .87은 **같은 전이 함수족 안에서 수정 후 따로 남겨 둔 위치**이며 독립적인 광범위 문제 검증으로 세지 않는다.

case5의 최종 작업량은 이전 정책보다 30.52% 감소했다. 다만 시간 중앙값은 이전 0.369166 ms, 새 정책 0.369637 ms였고 paired 비용비 중앙값도 1.069이므로, 이번 자료에서 case5의 벽시계 개선을 선언하지 않는다. 직접 RODAS는 다섯 반복 모두 더 빨랐다. decay도 새 정책의 작업량은 그대로이고 직접 DOPRI보다 느렸다. stiff-forced는 작업량이 동일하며 측정 산포가 커서 시간 우위를 결정할 자료가 부족하다.

relaxation에서는 같은 창의 반사실 implicit 비교를 추가해 RHS가 749→813, 8.54% 증가했다. 이 비용은 다른 창의 과거 작업률만으로 explicit 복귀를 판단하지 않기 위해 지출한 실제 비용이다. 다음 최적화는 비교의 유효성을 유지하면서 productive comparator의 상태·workspace를 이어 쓰고, 이미 충분한 근거가 있는 창에서는 비교를 생략하는 것이다.

## 두 번의 회귀와 최종 수정

case5의 첫 구현은 2,463 RHS, 양방향 변화 신호만 추가한 중간 구현은 2,763 RHS를 썼다. 두 결과를 각각 `switching/native/`와 `switching/transient_diagnostic/`에 보존했다. 초기 과도구간에서 DOPRI 스텝이 커지고 작업률이 빠르게 낮아지는 동안 첫 prefix의 부정적 implicit 비용 근거가 계속 재사용된 것이 첫 회귀의 원인이었다.

중간 구현은 개선 방향의 변화를 감지했지만, 아직 과도구간을 포함한 prefix를 다시 비교하고 새 부정적 근거의 backoff를 길게 잡아 재차 지연되었다. 최종 구현은 변화가 감지된 batch가 끝나는 **새 endpoint에서 짧게 갱신할 비교를 예약**한다. 그 결과 case5는 1,311 RHS로 줄었다. 초기 조건에만 맞춰 전역 pilot 간격을 낮추는 대신, 적응 제어가 드러낸 regime 변화와 비교 근거의 유효기간을 연결한 수정이다.

최종 결과는 **45개의 새/이전 정책 비교와 45개의 새/직접 대안 비교**다. 이들은 아홉 문제의 반복 실행이다. 세그먼트의 probe 여부·commit 여부는 기록되어 있으나, 각 전환 시점마다 독립적인 경제성 정답이 제공된 자료는 아니므로 개별 전환 오탐률은 계산하지 않았다. 비용 구간에 의한 조건부 선택 보장과 이 실측 비교를 구분한다.

## 병렬 실행과 보정기의 채택 범위

병렬 자료는 처음 실행한 세 단계, 총 45개 배치 결과를 그대로 재사용한다. 단계별 다섯 평가 배치의 직접 최선 비용과 adaptive 전체 비용은 각각 **0.702/1.520 ms, 4.302/5.759 ms, 4.539/20.545 ms**였다. adaptive 비용에는 calibration과 최초 pool 생성비가 포함되고, calibration 안의 warmup은 중복 합산하지 않았다. 고의로 epoch를 바꾸지 않은 비용 변화에서는 두 번의 이탈 관측 후 증거를 무효화하는 동작을 확인했다. 그러나 전체 경제성은 세 단계 모두 개선되지 않았다. 짧은 사용 구간에서는 보정을 시작하기 전의 탐색 예산과 예상 회수 가능성을 먼저 판단해야 한다.

causal 보정도 기존 고정 격자 실험을 재사용한다. 물리 출력 예산으로 중단하면 candidate RHS와 구간 잔차 검사 횟수의 합이 16,818→10,513, correction rounds가 1,018→533으로 감소했다. 해석해 endpoint 오차는 2.03e-9로 진단용 1e-6 상한을 통과했다. 각 stage의 원래 목표 잔차로부터 계산한 local 출력 상한은 1e-9 이하로 유지되었다. 이 결과는 derivative-free 보정의 내부 정밀도를 필요한 물리 오차에 맞추는 이득을 지지한다. 단순 scalar 문제의 순차 RK는 1,792 RHS만 사용하므로, 보정기는 그 경로를 대체할 기본 선택이 아니다. 실제 병렬 속도는 아직 이 실험에서 측정하지 않았다.

## 다음 성능 검증의 초점

1. rotation의 약 5.21배 직접 경로 대비 비용을 스케줄링, wrapper 관리, pilot, linear algebra로 분해한다. RHS 증가가 약 11%인 것만으로 큰 시간 차이를 설명할 수 없다.
2. case5처럼 작업량 감소가 시간 감소로 이어지지 않는 짧은 실행은 반복 묶음의 총시간과 분해된 카운터를 함께 측정한다. 현재 오차 기준은 그대로 둔다.
3. 같은 함수족의 위치 변경 검증을 넘어, 다른 전이 폭·비정규 성분·강성 완화·output cadence·callback 비용을 갖는 소수의 보류 사례를 비교한다.
4. implicit session을 유지해 productive 비교와 본 적분의 상태·controller·workspace를 연결하되, method/model/chart epoch가 바뀌면 무효화한다.
5. 병렬 calibration은 호출 전에 남은 작업량과 비용 예산을 확인하고, 비용 증거의 불확실성과 재탐색 비용을 함께 보고한다.

최종 그림은 `figures/final_native/native_selection_pilots.{png,svg,pdf}`이다. 전체 solver의 production 판정은 계속 보류한다. 이번 결과는 수정된 선택 정책의 일부 전이·진동 조건에서 효용과, 원래 잔차 기반 보정의 정밀도 배분을 실제 코드로 확인한 범위에 해당한다.
