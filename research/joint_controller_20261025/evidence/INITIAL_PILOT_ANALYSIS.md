# 첫 통합 pilot의 결과와 수정 근거

이 문서는 `NATIVE_PILOT_SUMMARY.json`과 그 안에 해시가 연결된 최초 native 출력에 대한 분석이다. 이후 수정본의 결과로 대체하지 않는다. `figures/initial_native/native_selection_pilots.png`는 이 자료만으로 생성하고 직접 열어 확인했다.

## 탐색 감소의 이득과 역효과

같은 물리 endpoint 오차 상한으로 일곱 문제, 세 경로, warmup 1회와 측정 5회를 비교했다. 최초 총 126행 중 측정 105행 모두 완주 및 물리 오차 상한을 통과했다. 표의 시간은 각 경로의 중앙값이며, paired ratio 중앙값과 구분한다.

| 문제 | 이전 / 새 정책 RHS | 이전 / 새 정책 시간 | 관측 |
|---|---:|---:|---|
| rotation | 6,395 / 5,804 | 2.470 / 1.321 ms | 버린 probe RHS 1,150→559, 두 정책 모두 RODAS committed 시간 0 |
| case5 | 1,887 / 2,463 | 0.340 / 0.367 ms | 부정적인 초기 pilot 이후 재탐색을 미뤄 명시법 96시도·576 RHS 증가 |
| transition-47 | 162,308 / 31,122 | 17.705 / 9.155 ms | 이전 정책은 implicit 진입 없음; 새 정책은 마지막 약 0.452 시간 구간에서 implicit 사용 |
| transition-91 | 34,749 / 30,215 | 6.405 / 5.659 ms | 뒤늦은 전이에도 재탐색 및 implicit 진입 유지 |
| relaxation | 749 / 813 | 0.248 / 0.253 ms | 같은 창의 implicit 반사실 비교를 추가해 64 RHS 증가; 선택 정확성을 검사하는 비용으로 기록 |

case5의 초기 RODAS pilot은 같은 짧은 prefix에서 406 작업단위를 썼고 DOPRI는 193을 썼다. 그때의 비용비 2.104를 이후 구간까지 유지한 것이 문제였다. 다음 명시법 batch에서 제안 스텝은 5.1068e-7→3.5111e-6, **6.875배 증가**했고 단위 물리 시간당 작업은 2.9834e7→2.5478e6, **11.710배 감소**했다. 그 뒤의 implicit pilot은 38 대 192 작업단위로 유리해졌다. 최초 정책은 비용 악화만 재탐색 신호로 삼아 이 개선 방향의 regime 변화에서 이전 근거를 무효화하지 못했다.

이 경우의 수정은 고정 cooldown을 무조건 짧게 하는 것이 아니라 **스텝 크기와 작업률의 충분히 큰 양방향 변화에서 과거 비교의 유효성을 재평가**하는 것이다. 이 진단은 case5에서 확인했으므로 수정 후 case5를 회귀 검사로 사용한다. 추가 전이 위치 .43과 .87은 수정 후 검사용으로 분리한다. 최초 .47과 .91 결과를 새 holdout처럼 다시 이름 붙이지 않는다.

`pilot_count`는 implicit 진입 pilot뿐 아니라 동일 창에서 수행한 RODAS 복귀 비교도 포함한다. 최초 요약의 `median_implicit_entry_pilots`는 이 넓은 카운터를 가리키는 과거 필드명이며, 후속 요약에서는 `median_rodas_probe_batches`와 명시적 의미 설명을 사용한다. `is_probe=true`이고 `committed=true`인 생산적인 비교도 가능하므로, 버린 비용은 반드시 `!committed`로 따로 집계한다.

## 병렬 실행: 무효화는 작동했고 탐색비 회수는 실패했다

세 단계마다 64개의 실제 logistic ODE를 다섯 번 실행했고, serial/parallel/adaptive 출력의 순서 및 값이 같았으며 물리 endpoint 상한 1e-7을 통과했다. 다음 표는 초기 pool 생성비를 첫 단계에 한 번만 더하고 calibration에 이미 포함된 warmup은 다시 더하지 않은 값이다.

| 단계 | 최선의 직접 경로 전체 비용 | adaptive 전체 비용 | 포함 범위 |
|---|---:|---:|---|
| 짧은 작업 보정 후 | 0.702 ms | 1.520 ms | 평가 5회 + 최초 pool + calibration |
| 고의로 epoch를 유지한 비용 변화 | 4.302 ms | 5.759 ms | 평가 5회; 새 calibration 없음 |
| epoch 갱신 후 | 4.539 ms | 20.545 ms | 평가 5회 + 새 calibration |

고의로 오래된 epoch를 유지한 단계에서는 두 번의 비용 이탈 관측 후 근거가 무효화되었고, 이후 세 번은 serial로 실행되었다. 이는 감지와 fallback의 실제 동작 근거다. 그러나 세 단계 모두 전체 비용은 직접 경로보다 높았다. 첫 단계에서 보정 후 dispatch만 빠르게 보이는 자료로 전체 성능 개선을 주장할 수 없다. 새 calibration을 시작하기 **이전**에 남은 실행량·탐색 예산·예상 이득을 확인하는 기능이 필요하다. 이미 지출한 보정비는 이후 dispatch 선택의 sunk cost지만, 보정을 시작할지 판단할 때에는 미래 비용이다.

마지막 단계에서는 보수적 표본 범위와 진입 여유 조건 때문에 serial이 유지되었으며, 실제 평가에서는 parallel이 자주 더 빨랐다. 세 쌍의 timing 표본 범위는 미래 비용에 대한 확률 보장 구간이 아니다. 이 결과는 false positive 억제와 missed opportunity 사이의 조정을 위한 다음 자료로 보존한다.

## 인과적 stage 보정: 내적 정밀도를 출력 예산에 연결

`y'=-y^3`, `y(0)=1`, `[0,1]`의 동일한 256개 고정 스텝에서 원래 stage 잔차를 이용한 출력 오차 예산이 correction을 실제로 중단시켰다. Jacobian/JVP/AD/Newton callback은 사용하지 않았다.

| 항목 | 잔차를 일괄 1e-14까지 감소 | 물리 출력 예산에 맞춰 중단 |
|---|---:|---:|
| candidate RHS | 7,900 | 4,990 |
| 구간 연산 잔차 검사 | 8,918 | 5,523 |
| 두 종류 평가 횟수 합 | 16,818 | 10,513 |
| correction rounds 합 | 1,018 | 533 |
| 해석해 endpoint 오차 | 5.33e-15 | 2.03e-9 |

평가 횟수 합은 37.49%, correction rounds는 47.64% 줄었다. 두 종류 평가의 비용은 다르므로 합을 시간이나 FLOP으로 표현하지 않는다. local stage 출력 상한은 1e-9이고 두 궤적의 endpoint는 진단용 1e-6 상한을 통과했다. rounds는 병렬 Jacobi 보정의 직렬 모사이며 실제 병렬 속도 측정은 수행하지 않았다. 이 작은 scalar 문제에서는 순차 native RK의 1,792 RHS가 더 저렴하므로, 해당 보정기를 scalar 기본 경로로 선택할 근거는 없다. 결과의 기여는 보정기를 쓸 만한 더 큰 문제에서 불필요한 root polishing을 물리 출력 예산으로 줄이는 구성에 있다.
