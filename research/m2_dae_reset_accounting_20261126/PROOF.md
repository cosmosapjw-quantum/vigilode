# Reset and guard boundary accounting, not a new physical certificate

Freeze original source, physical solver, tolerances, event decisions, quota policy and legacy serialization. For any normally returning Result boundary, AttemptCount records one started and one returned iff Ok. Returned means the operation returned a value, not that a physical condition or transaction was qualified. Within a parent boundary, child operations are counted independently; parent and child counts cannot be summed as an exclusive operation or FLOP count. A panic is outside the contract. Work within a failing lower-level call that did not return an independent counter remains unknown.

GuardKernelAudit records reached original-source interval evaluations, actual PreparedSchur preconditioner requests and successful whole RHS counts, and reduced column bound calculations. Original guard build and reset image are separate boundaries: a guard build may succeed before the component image fails. NativeResourceAudit retains guard and guard-difference kernel counts, comparison return outcomes and positive decisions separately. Cached comparison lookup is not a new computation; counts are only added for the actual comparison. Difference components use the original source, authenticated slab and existing SchurPicard route. No event authority follows from a diagnostic count.

ResetKernelAudit records vector branch proof calls, the initial source projection report (including failure work from M2-03d.3a), subsequent original-source evaluations, separate preconditioner RHS, reduced column proofs, actual Picard images and strict inclusion decisions. A tube can fail after one or more branch proof returns; those counts survive. Synchronization retains actual completed per-component and Green phi calls (including calls before a later error), not an inferred count from the number of retained final components. Original physical proof objects and arithmetic order are unchanged. The old public functions delegate to the same recorded kernel with discarded fixed-size counters. Retained work is separate from output-owned physical reports. All interval inclusion, branch, root and residual conditions remain unchanged.

The conserved-chain facade records actual native request identity, quotas and returned Stats for both guarded and terminal epochs. Before native API invocation, measured attempts are Some(0). Once invoked without returned Stats, measured attempts remain None; even invalid option refusal is conservatively unknown at this outer boundary. Source inspection of solve.rs shows validate/adaptive.validate/build before dispatch, and multiple later driver_error conversions; no general classification of every Err as zero is sound. No driver implementation modified. No native quota refund, no change in stop selection. Each actual transition attempt has its own receipt, preparation and table boundary, cell, kernel, restart, transport, actual gap checks and strict-negative results; committed is independent of all individual return statuses. Existing debit on Err (remaining quota or cap), on returned work (retained counts) and conservative Picard debit 8*charged_cells+1 are unchanged. Boundary counts do not confer authority and do not mutate accepted state. Snapshots exclude subsequent user queries.

The exact algebra of nonnegative partition and debit is checked with MathHarness/Wolfram; claims about actual implementation require the executed portfolio and refusal tests. New failure probes include genuine branch contraction failure and Picard expansion refusal, plus intentionally malformed copies of authentic guard/tube reports solely to exercise error paths after successful subwork. The malformed inputs are not physical evidence. All existing physical CELL receipts and work metadata are compared against the published prior commit.
