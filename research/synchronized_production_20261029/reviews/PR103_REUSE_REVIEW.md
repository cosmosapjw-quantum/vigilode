## Critical native reuse findings

1. **Electron-weight preparation is not enclosed for arbitrary accepted isotope inputs.** `certify_mu` and `electron_event_dual_upper` form `[wh,whe,2*whe,wli,2*wli,3*wli]` in ordinary binary64 and then treat each value as an exact point. PR95 and the new theorem instead interpret isotope inputs as exact represented numbers and apply exact integer charge factors. Doubling is exact when finite, but multiplication by3 generally rounds. For example, the represented value `wli=1+3·2⁻⁵²` has exact triple `3+9·2⁻⁵²`; nearest-even binary64 rounds it to `3+8·2⁻⁵²`. Thus the point used for e₅ need not contain the theorem's e₅. Subsequent interval padding may happen to cover particular outputs, but no proof covers this missing input enclosure. All seven retained native fixtures use isotope values for which the charge factors are exact. Before broad reuse, propagate interval electron coefficients from outward integer multiplication, add an explicit coefficient discrepancy enclosure, or restrict/admit only exactly representable charge products and document that restriction. No failing native output is claimed from this static finding.

2. **Public event-dual entry point omits the arithmetic-mode guard.** `certify_mu`, `rational_whole_error`, and `electron_event_sign` call `check_arithmetic`; `electron_event_dual_upper` does not. Its outward claim therefore requires an undocumented unchanged arithmetic-mode premise at that entry. Add the same guard or an explicit validated arithmetic-context contract. This review did not alter FP modes or execute an adversarial test.

3. **Interval validity must be enforced at public boundaries.** `Iv` exposes public fields, permitting callers to bypass `Iv::new`. `electron_event_sign` receives two such intervals without validating finite ordered endpoints at entry. Later arithmetic often rejects malformed input, but that is not a complete input-validity contract. Make construction invariant-preserving or validate both intervals before use. This is API hardening needed before a certificate provider is exposed broadly.

4. **Source strings and metadata are premises, not authentication.** Source/binding/clock equality and a nonempty unit string do not establish owner-accepted isotope arrays, actual rate enclosures, clock transformation, model coverage, norm transport or a physical capsule. `Bound.chosen_rate_endpoint` belongs to the maximizing rounded upper expression; it is not automatically an exact attaining witness. The theory correctly distinguishes rounded upper bounds from exact equality; callers must preserve that distinction.
