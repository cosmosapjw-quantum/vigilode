# Preregistration: GCRO-DR with a verified recycle pair on reuse (integrated DAG node INT-01)

## Question

L-0046 (R-NEXT-03) attributed every recycled-GCRO-DR failure on the frozen Brusselator systems to recycling, and a
post-hoc probe found the mechanism: a recycle update returns a pair `(U, C)` that breaks `M^-1 A U = C`, and because
the operator is unchanged the next solve reuses it unchecked. The node failed its gate on an accounting rule (the
trace omitted the cycle a solve aborted in), and the review's acceptance test on unused synthetic cases was not met
(its held-out set failed for every solver, cold GMRES included). Does checking the pair before reuse remove the
recycle-induced failures, with all work charged, no false convergence, and on a fresh family fixed now?

## Changes (opt-in; defaults unchanged)

`rodas5p-krylov`:

- `GcrodrReusePolicy { reset_factor: Option<f64>, verify_reuse: Option<f64> }` and
  `solve_gcrodr_with_policy(op, pc, rhs, x0, config, state, residual_scale, workspace, policy, trace, counters)`.
  `solve_gcrodr_traced(.., reset_factor, ..)` becomes this with `verify_reuse: None`; the untraced solve is
  unchanged.
- `verify_reuse = Some(tol)`: when the carried pair would be reused on the same system, each `u_j` is applied once
  (charged as refresh products) and `delta = max_j ||M^-1 A u_j - c_j||_2` is formed (the `c_j` are orthonormal).
  If `delta > tol`, the pair is rebuilt from these images exactly as after an operator change (`orthonormalize_pair`;
  no further products). Otherwise it is reused as before. Each check is recorded in the trace (`rank`, `defect`,
  `rebuilt`).
- The trace records the cycle a solve aborts in (`aborted: true`, with the products charged since the cycle began),
  so that every charged product is in a cycle record or in the outside-cycle total.

## Controls

On each system sequence, solved in order with one carried state per control: A cold GMRES, B cold GCRO-DR,
C recycled GCRO-DR, D recycled with the stagnation reset `q = 0.5` (as in L-0046), and **E recycled with
`verify_reuse = 1e-8`** (no reset). GCRO-DR settings as L-0046: restart 40, recycle dimension 8, rank tolerance 1e-12,
`atol = 1e-14 |gamma|`, identity preconditioner.

The tolerance 1e-8 is fixed now from L-0046's post-hoc data: healthy carried pairs had defects of 1e-15 to 1e-12, and
the broken ones 6e-4 to 2.59.

## Systems

1. **L-0046 sets, regenerated by the same code:** the trajectory set (first 40 attempts of the GMRES U-form run on
   Brusselator n = 50, rtol 1e-11, budget 200) and the one-step set (h = 1e-4, 1e-2, rtol 1e-12, budget 4000).
2. **Fresh family (not used by any earlier node):** 1-D convection-diffusion-reaction operators
   `W = I - tau (nu D2 - c D1 - r I)` on n = 120 interior points with Dirichlet ends, Peclet numbers
   `{0.5, 5, 50}` and `tau in {1e-3, 4e-3}`; each sequence has 6 operators (`tau` scaled by `1 + 0.02 k`), each with
   8 right-hand sides `W u_i`, where `u_i` mixes a smooth profile and a seeded random vector (seeds 9001 + i). rtol
   1e-9, budget 400. The family's parameters were chosen so that cold GMRES converges on it; only control A was run
   on it before the recorded run.

## Gate

**PASS** if all hold:

1. **Defaults unchanged.** With the default policy, `solve_gcrodr_with_policy` is bitwise the plain solve and the
   traced solve (solution, report, counters, state) on the contract systems, and the existing R-NEXT-03 contract
   tests pass.
2. **Reproduction.** Control C fails on the same solves of sets 1 as in L-0046's `RESULTS.json` (21 failures).
3. **Mechanism removed.** Control E has no failure on sets 1 where cold GCRO-DR (B) succeeds.
4. **Accounting.** For every GCRO-DR solve of every control and set, the counters equal the traced total, each
   completed cycle satisfies L-0046's per-cycle rule, each aborted cycle has at most `restart + 2` products, and the
   products outside cycles are at most one residual per loop entry plus the refresh and check products plus one
   final check.
5. **No false convergence.** Every success of every control in every set has an independent true residual at most
   the threshold times `1 + 1e-12`.
6. **Fresh family.** Control E fails on no more fresh solves than control C.

Otherwise **FAIL**. Reported, not gated: failures and products per control and set, the number of checks, rebuilt
pairs and the defect distribution, and E's products relative to B, C and D. A contract test also corrupts a carried
image on purpose and checks that E rebuilds it. No Ritz-value-based certificate; no timing.

## Stop condition

Operator products (failures):

E checked 280, 14 and 252 carried pairs and rebuilt 11, 4 and 0 of them. Defects of the pairs it kept were at most
2.5e-13 on the fresh family and up to 2.2e-9 on the one-step set.

**Why E still fails twice.** Both failures start from a carried pair with defect 2.2e-9, under the tolerance. In the
first cycle, `max |C^T V|` is already 0.64, and the true residual then grows each cycle (4e-8, 2e-3, 4e4, ... to
1e282) until a product overflows. The recycle projection removes almost all of the residual (2.2e-4 to about
1e-12 here), so a defect `delta` in unit-norm columns becomes a component of order `delta ||C^T r||` in the
recomputed residual. That component is comparable to the projected residual itself. The first Arnoldi vector then
has an O(1) part along `C`. The small least-squares problem assumes `[C V]` is orthonormal, so it no longer
minimizes the true residual, and the residual can grow. So an absolute tolerance on the defect is the wrong scale.
The defect has to be small relative to `||r - C C^T r|| / ||C^T r||`, or `v_1` has to be projected against `C` again.

On the fresh family, recycling pays: C and D use 0.80x of cold GCRO-DR's products and 0.71x of cold GMRES's. E costs
6% more than C. On the Brusselator sets, recycling saves nothing, as in L-0046.

### Post-hoc diagnostic (after the recorded run; not part of the gate)

`tests/int01_posthoc_tolerance.rs` (`POSTHOC_TOLERANCE.json`) reruns the study with E's tolerance at 1e-10 and at
1e-12. The command is
`INT01_POSTHOC_TOL=<tol> INT01_POSTHOC_OUTPUT=<absolute path of POSTHOC_TOLERANCE.json> cargo test --release -p rodas5p-integrators --locked --test int01_posthoc_tolerance -- --ignored --test-threads=1`.

| Tolerance | Trajectory, E (failures) | One-step, E (failures) | Fresh, E (failures) |
|---|---|---|---|
| 1e-10 | 14,392 (0) | 736 (0) | 35,380 (0) |
| 1e-12 | 14,357 (0) | 736 (0) | 35,380 (0) |

Both settings remove every failure, with accounting and true residuals intact. This tolerance was chosen after
seeing the failures, so it is not evidence for any fixed value. A residual-relative check, or a second projection
of `v_1`, follows from the mechanism above and would need its own preregistered node. Claim ceiling: these frozen
systems; no Ritz-value-based certificate; no timing.
