# 선택 결과를 중심으로 한 다음 벤치마크

목표는 실제 adapter가 선택한 경로의 정확도와 비용을 측정하고, 더 나은 대안이 관찰될 때 선택에 사용된 정보와 누락된 정보를 찾는 것이다. 모든 방법과 스레드 수의 곱을 반복하지 않는다.

## 최소 실행 단위

하나의 비교 단위는 같은 ODE, 매개변수, 시작 상태, 시작·종료 시각, 물리 오차 척도와 허용 상한, 참조해, 출력 요구, 호스트, 소스 트리, 빌드 설정, 비용 범위를 공유하는 **결정 구간**이다. 반복 블록도 동일해야 한다. 시간과 오차 상한은 `float.hex()` 형식으로 보존한다. 좌표변환 내부의 허용오차가 달라도 최종 판정은 동일한 물리 상태·출력 척도로 수행한다.

1. 새 adapter의 실제 선택을 먼저 기록한다. 모델의 선언된 구조, 관측된 작업량, 스텝 제안과 수락 이력, 선택 이유 및 권한을 함께 기록한다.
2. 선택 직전의 물리 상태를 저장하고 그 지점에서 선택된 방법과 가장 관련 있는 대안 1개를 비교한다. 정확도·완료 조건을 만족하지 못한 방법은 빠른 대안이 아니다.
3. 대안이 의미 있게 더 좋으면 원인 가설에 해당하는 두 번째 대안만 추가한다. 예: 같은 방법의 스텝 이어받기 유무, 같은 수치 경로의 직렬/병렬, 원래 좌표/선언된 cofactor 좌표, 상수/시간변화 위상 처리.
4. 정책 조정에 사용한 구간과 최종 평가 구간을 분리한다. 전환 직후, 빠른 초기층 이후, 주파수가 증가하는 후반, 큰 격자의 정상 진전 구간을 따로 포함한다.
5. callback이 부작용을 일으키면 shadow 실행을 직접 반복하지 않는다. 순수 RHS의 분리된 복제 또는 별도 프로세스와 소유된 효과 기록을 사용한다. BASS/REI의 accepted-only journal과 acknowledgement 규칙을 그대로 우회하지 않는다.

적응적인 solver의 내부 이력은 방법마다 다르다. 비교 전에 초기화 정책을 정한다: 예컨대 모두 동일한 물리 checkpoint에서 새로 시작하거나, 실제 incumbent는 이력을 유지하고 challenger의 준비 비용을 전부 포함한다. 그 정책을 `timing_scope_sha256`이 가리키는 설명에 포함한다. 같은 시작 상태만으로 warm/cold 비용이 같다고 간주하지 않는다.

## 비교량

각 구간에서 선택 비용은 서로 겹치지 않는 네 항의 합이다.

\[
 C_{\rm selected}=C_{\rm solve}+C_{\rm setup}+C_{\rm probe}+C_{\rm transition}.
\]

풀 준비, calibration, 버려진 pilot와 변환 준비도 실제로 발생한 구간에 한 번씩 청구한다. 이미 solve 시간에 포함된 비용을 다시 더하지 않는다. 캠페인 공통 준비 비용은 별도 합계를 남기고, 구간별 배분 규칙을 비용 범위 문서에 고정한다. 시스템 CPU와 wall time, callback 중첩 시간을 서로 더하지 않는다.

같은 물리 오차 상한 \(E_*\)을 만족하는 실제 관측 후보 집합을 \(\mathcal A_w\)라 하면,

\[
 R_w=C_{\rm selected}/\min_{a\in\mathcal A_w}C_a,\qquad
 \Delta C_w=C_{\rm selected}-\min_{a\in\mathcal A_w}C_a.
\]

여기서 최소값은 **시험한 적격 후보 중 최소**다. 전역 최적 방법이나 정확히 같은 달성 오차의 비교를 뜻하지 않는다. 서로 다른 소스·호스트의 오래된 행을 섞어 이 비율을 계산하지 않는다. 실패한 선택과 참조 미확보 선택에는 비율을 부여하지 않고, 완료·정확도 상태를 먼저 보고한다. 적격 대안이 없으면 추가 비교 정보가 없다는 결과를 남긴다.

오차 값과 참조 불확실도는 같은 물리 척도에 있어야 한다. 판정은 입력된 binary64 값의 정확한 합 \(E+U\le E_*\)으로 한다. `empirical` 불확실도는 수치적 비교량이며 수학적 인증 상한으로 승격하지 않는다. 분석기는 이 물리적 의미를 재증명하지 않으므로 raw 검증과 척도 산출은 실행 측의 책임이다.

## 원인별 다음 실험

| 관찰 | 다음 비교 | 필요한 계측 |
|---|---|---|
| 거의 모두 수락하지만 진전이 느림 | 현재 좌표와 선언된 cofactor/slow 좌표; 또는 explicit/implicit 짧은 동구간 비교 | 시도 전후 h, 제한 사유, 오차 추정, RHS 수, 실제 진전 |
| 구간마다 처음부터 작은 h | h0 재시작과 실제 다음 h 보존 | 선택 전후 h, controller 이력 유효성, 준비 비용 |
| 진동 후반 오차 증가 | 진폭/위상 오차와 물리 변환 오차 분해 | 위상 누적, \(\omega(t)\), 실제 상태 오차, 변환 조건수/상계 |
| switcher가 느린 방법 유지 | 동일 checkpoint에서 challenger를 1회 제한 비교 | probe 시각, 관측 비용, 재평가 기회, 전환 이득과 준비 비용 |
| 스레드 증가가 느림 | 같은 방법·출력의 직렬과 한 병렬 후보 | wall/user/system, context switches, batch 크기, 풀 준비, 중첩 여부 |
| 늦은 종료·timeout | 더 짧은 동일 물리 구간의 진전 계측 | accepted/rejected 수, 현재 t, callback 시간, 오류와 종료 상태 |

위 항목은 원인 가설을 판별하는 실험이다. 작은 h만으로 stiffness를 확정하거나, 높은 system CPU만으로 동기화가 원인이라고 판정하지 않는다.

## 입력·실행·산출물

`selection_window.schema.json`은 입력 구조다. 구현의 `analyze_selection.py`는 Python 표준 라이브러리만 사용하며, 과거 측정 파일을 수정하거나 solver를 시작하지 않는다. 후보별 `raw_verified=true`와 SHA256 값은 상위 원시자료 검증기의 출력이어야 한다. 이 분석기는 파일 해시의 진실성이나 RHS의 물리적 타당성을 대신 검증하지 않는다.

```bash
python3 -B research/adapter_research_20261025/selection_benchmark/analyze_selection.py \
  /path/to/NEW_SELECTION_WINDOWS.json \
  --output /path/to/NEW_SELECTION_ANALYSIS.json
```

출력 경로는 새 파일이어야 한다. 오류·중단·참조 부족·동일성 불일치를 보존하며, 원인 이름이 없는 행에 임의의 물리적 원인을 만들지 않는다. 주어진 후보만으로 제한된 관측 비용 비율을 계산한다. binary identity는 각 행에 보존하되 방법마다 다른 바이너리는 허용한다. 공통 소스 트리·빌드 설정·호스트·작업 범위는 일치해야 한다. 외부 solver 비교는 별도 명시적 source map을 갖춘 상위 비교 계약에서 수행한다.

`SYNTHETIC_CONTRACT_INPUT.json`과 해당 출력은 분석기 작동 예제이며 실제 속도 측정이 아니다. 단위검사는 선택 실패, 빠르지만 부정확한 대안, early exit, 다른 상태/호스트/소스, 비용 중복, 참조 미확보, NaN/Inf/bool, 중복 후보와 JSON 키 등을 포함한다.

## 로컬 인계

먼저 `/tmp/vigilode-local-run-20261024.geLVCp9Q`의 실제 raw를 읽기 전용으로 조사하고 보존한다. 최신 중지 패킷의 해시와 raw의 실제 대응을 확인한다. 기존 1,539개 작업을 새 참조나 새 판단 기준으로 덮어쓰지 않는다. 새 실행은 별도의 소스 고정 디렉터리·식별자를 사용한다. 현재 정지된 장기 캠페인은 자동 재개하지 않는다.

정밀한 새로운 수학 유도·불명확한 원인 심사에만 사용 가능한 `astra`/`ultra`와 연구 플러그인·스킬을 배정한다. 그 이름의 실행 능력이 실제 호스트에 없으면 명시하고 가용 경로로 제한한다. 자료 추출·정해진 테스트·빌드·로그 수집·이미 확정한 작은 수정은 저예산 경로에서 수행한다. 긴 로그나 raw 전체를 고비용 모델에 넣지 말고, 실패를 재현하는 최소 코드·대표 계측·정확한 source identity를 전달한다.
