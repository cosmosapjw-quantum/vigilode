# Homotopy Order-Aware Policy and Rayon Screen — Design Specification

Date: 2026-08-08
Base commit: `1e322cfbf5802dbabc6c94afce0e072a667f2081`
Branch: `homotopy-order-policy-v0.6`

## Goal

Determine whether an output-defect budget that scales with the embedded estimate and/or with
`h^6` preserves the protected fifth-order RODAS5P trend while retaining a nonempty low-depth
homotopy regime. Run the independent policy and trajectory jobs through a bounded local Rayon
thread pool so the same Rust implementation can measure real multicore throughput without
changing the numerical method.

## Protected object

The stage candidates, exact nonlinear target certificate, protected sequential fallback,
RODAS5P coefficients, and common `faer` backend remain unchanged. The cycle changes only the
accept/reject policy and the outer execution backend used for independent cases and trajectories.

## Output-budget policies

All budgets are dimensionless because `E_out` and `E_emb` are WRMS quantities.

1. Absolute:
   `B = epsilon`.
2. Embedded-relative:
   `B = eta E_emb`.
3. Step-power:
   `B = epsilon_ref (|h| / h_ref)^6`, where `h_ref` has the same time unit as `h`.
4. Mixed:
   `B = min(eta E_emb, epsilon_ref (|h| / h_ref)^6)`.

The API rejects nonfinite parameters, negative budgets, nonpositive `h_ref`, and nonpositive
step sizes. A policy decision never bypasses the existing `embedded + algebraic <= 1` gate in
adaptive use. Fixed-step order screens may force the time step while still enforcing the output
budget.

## Calibration and holdout

The frozen cycle-1 one-step candidates are regenerated by the unchanged path kernel and split by
a deterministic case identifier hash. Policy parameters are ranked only on the calibration half.
The holdout half reports false accepts, low-depth acceptance, fallback fraction, and scalar work
without retuning.

Policy grid:

- absolute `epsilon in {0.1, 0.03, 0.01}`;
- embedded-relative `eta in {0.5, 0.2, 0.1, 0.05}`;
- step-power `epsilon_ref in {0.1, 0.03, 0.01}`, `h_ref=0.04`, exponent `6`;
- mixed `eta in {0.5, 0.2, 0.1}` crossed with the same step-power values.

## Global trajectory screens

At most the best zero-false-accept policy from each policy family advances to fixed-step
trajectories. The methods are the protected sequential control and the predeclared low-depth
homotopy configurations `q=0,1,2`, plus `q=7` as a correctness oracle. Screens cover:

- manufactured vector global order;
- Prothero–Robinson stiff/nonlinear trajectory;
- nonnormal noncommuting-mass trajectory.

A method-policy pair is promoted only if its pre-roundoff observed order remains compatible with
five, stiff error does not regress relative to the protected control, holdout false accepts are
zero, and a low-depth accepted regime remains nonempty.

## Parallel execution

Use `rayon 1.12.0` with a local `ThreadPoolBuilder`, never the process-global pool. Independent
case/config jobs and independent policy/trajectory jobs run in this pool. Results are sorted by
stable keys before serialization so thread count does not change scientific output.

`faer` remains sequential in this cycle to avoid nested oversubscription. Portable `std::simd`
is not used because it is not stable on Rust 1.94.1. Existing `faer`/`pulp` kernels and LLVM
may still use runtime SIMD and autovectorization. Manual `std::arch` kernels are outside scope
until profiling identifies a vector kernel that dominates runtime.

## Failure semantics

- A failed path or certificate is recorded and never accepted.
- A policy that produces a nonfinite budget fails explicitly.
- Rayon panics propagate and fail the screen.
- Failed speculative steps do not commit integrator or recycle state.
- Exact sequential fallback remains the scientific result when the fast path is rejected.
